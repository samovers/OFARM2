| D17 | **Bounded self-acceptance for farm-owned structure assertions.** A party holding both `ASSERT_STRUCTURE` and `REVIEW_ACCEPT` on a farm may self-accept low-consequence `STRUCTURE_ASSERTION` commits describing that farm's own G1 setup identities (Farm/Field/CropCycle/Equipment/AppliedResource) — but only after **semantic** validation of payload-internal refs (kind/type consistency, farm containment, party/evidence/binding/reference refs resolving to the right kinds, durable-evidence floor) and explicit supersession for an existing identity (D18). Implemented as a **named `StructureSelfAcceptancePolicy`**, never "all `STRUCTURE_ASSERTION`s self-review"; any structure assertion outside this bounded class routes to queued review with a distinct reviewer. Creates record-keeping structural state only — no external-truth, compliance, currentness, or scheme-binding claim. | Solo-farm onboarding shouldn't need advisor sign-off to register basic setup, but structure is governed substrate affecting later claims/materializations; **extends D8 narrowly as a recorded decision**, not an accidental consequence of the generic promotion path. Steward decision on PR #9 (2026-06-18). |
| D18 | **Explicit supersession required for existing structure identities.** A `STRUCTURE_ASSERTION` whose `identityRecordRef` already has in-force structural state must carry `supersedesConsequenceRef` naming **that identity's** current structural consequence; if absent (or it names another identity's / a non-current consequence) the commit is `RETAIN_DRAFT` with a registry-coded `RuntimeProblem` (`CORRECTION_REQUIRED`). The runtime **never** silently picks "latest wins" among multiple in-force structural consequences for one identity. G1 does not route the duplicate to review (no conflict-resolution state machine yet): no explicit supersession ⇒ no promotion. | Duplicate structural assertions are ambiguous; insertion order must never become hidden truth. Preserves deterministic current state, append-only history, and visible correction intent (correction = supersession). Steward decision on PR #9 (2026-06-18). |
| D19 | **Scheduled reference imports invalidate materializations by context-key drift, not broad-staling.** A new in-force `ReferenceSnapshot` changes the per-farm `ContextSnapshot` (the assembler folds the current reference snapshots into the context basis), hence the `MaterializationKey` — so a post-import NOW materialization never reuses a pre-import row (D12). The import runner therefore does **not** call an explicit broad-stale; this is accepted bounded debt for the single-writer pilot. An explicit `invalidate_for_sources` over a reference family is added only if a future use path could reuse a pre-import key. | Resolves the G2 hostile-review H2 "decide and record" obligation (folded into P1/P2). Single mechanism (D12) already covers it for the pilot; broad-staling deferred until a reuse path demands it. Recorded 2026-06-19. |
| D20 | **REJECT is a terminal, append-only review decline (M2 G5-1; spec `docs/REVIEW_DISPUTE_SEMANTICS.md`).** A reviewer's REJECT of a `PENDING_REVIEW` assertion appends a `ReviewDecision` (`reviewAction REVIEW_REJECT_OR_CONTEST`, `decisionOutcomeState REJECTED`, non-empty rationale; reviewer evidence optional) + a `REVIEW` edge, and **emits no `AcceptedEventConsequence`** — the queued assertion is never edited (Kernel rule 1); its disposition is **derived** REJECTED and it leaves the pending queue via the existing REVIEW-edge filter. Commit outcome is `RETAIN_DRAFT` (no consequence promoted; terminal-ness carried by the `ReviewDecision`, not by the outcome enum — ERRATA E-005). **No materialization is staled/invalidated** (a rejected claim was never an in-force basis member). REJECT is **terminal**: any later review of the same target is refused by the existing double-decide guard (`RETAIN_DRAFT`, `SUPERSEDED_RECORD_USED`, "already reviewed"); the lawful way forward is a **new capture** (correction = new payload, never reopen). Authority is the **distinct** `REVIEW_REJECT_OR_CONTEST` action (matrix `NO_INHERIT`; holding `REVIEW_ACCEPT` does not confer it). Reversing a rejection, CONTEST (G5-3), and SI grant specifics (P5) are out of scope. No invented reason codes or contract values; all enum values are shipped contract vocabulary. | Review/dispute behavior must land semantically before code (M2e); leaving REJECT's state effects to an "obvious default" would risk an in-place edit, a silent denial, or a re-promotable "rejection." Symmetric with acceptance, fully append-only, contract-clean. Steward-gated spec ticket. Recorded 2026-06-20. |
| D21 | **CONTEST opens an append-only dispute against an in-force consequence; resolution is supersession (M2 G5-3; spec `docs/REVIEW_DISPUTE_SEMANTICS.md` §6).** A CONTEST targets an **already in-force `AcceptedEventConsequence`** (`reviewedArtifactFamily ACCEPTED_EVENT_CONSEQUENCE`, the shared `REVIEW_REJECT_OR_CONTEST` action with `decisionOutcomeState CONTESTED`). It appends a `ReviewDecision` (CONTESTED, non-empty rationale; evidence optional) + a **`DISPUTE` edge** (consequence→decision) and **emits no consequence and no `LINEAGE_SUPERSEDES`**: the consequence is never edited and **stays `IN_FORCE`**, flagged disputed (its `inForceState` enum has no `DISPUTED`; `is_superseded` reads only `LINEAGE_SUPERSEDES`). Unlike REJECT, CONTEST **stales** dependent materializations (D12 via `invalidate_for_sources`); a disputed basis **blocks** high-consequence freeze (`DISPUTE_OPEN`), and `disputeStatus` becomes **derived** — `OPEN_DISPUTE`/`DISPUTED_BASIS` when an unresolved dispute touches the basis, closing the latent M4 over-claim (the hardcoded `views.py` `disputeStatus="NONE"`). The dispute **resolves only by supersession** — a governed CORRECTION that supersedes the disputed consequence (→ `CORRECTED`), reusing the existing supersession path; never an edit, never a silent clear. Commit outcome `RETAIN_DRAFT` (E-005). Dismissing an unfounded contest (`REVIEW_SUPERSEDE`) and SI specifics (P5) are out of scope. No invented reason codes or contract values; all enum values (`CONTESTED`, `DISPUTED_BASIS`, `DISPUTE_OPEN`, `recordClass DISPUTE`) are shipped contract vocabulary. | The latent M4 `disputeStatus` over-claim must close before any output claims "no dispute"; CONTEST's in-force target and materialization staling are the inverse of REJECT's queued-and-inert target, and must be settled before G5-4 codes them. Append-only, contract-clean, resolution reuses supersession. Steward-gated spec ticket. Recorded 2026-06-20. |
