# Look up the signed-in farm’s choice for Submit

Phase A for [#427](https://github.com/samovers/OFARM2/issues/427). The primary trust boundary is **read-only tenant command selection**. On the first-save path, return one immutable, verified choice for this farm or stop before the caller allocates a save batch. A successful read supplies evidence to the coordinator. The coordinator owns the decision to save. [Agreement with the transaction guard](OFARM2_Guarded_Operation_Claim_Call_RFC_v0_1.md#authority-and-call-order)

## What each owner supplies

| Owner | Evidence or decision |
| --- | --- |
| Tenant transaction manager and database access owner | The signed tenant binding on one live connection, the fixed read available to an ordinary session, and the ordering guarantee described below. The manager alone controls batch allocation and finalization. |
| [#431](https://github.com/samovers/OFARM2/issues/431) and the package owners | Independently admitted package bytes and the issued tuple of command ID, binding ID, version and digest. The version 2 design names `SUBMIT_OPERATION_CLAIM`, `ofarm.submission-command.operation-claim.v0.2`, version `0.2`. The action is `ASSERT_OPERATION_CLAIM`. |
| [#430 / setup design](https://github.com/samovers/OFARM2/pull/437) | The approved selection binding and its component inventory, and the immutable choice and activation batch committed together for one farm. A sealed bundle by itself supplies no choice. |
| #427 | Compare that farm’s choice with both independent bindings, verify the selected sealed bundle, and hold one result on that unit. |
| [#178](https://github.com/samovers/OFARM2/issues/178), [#425](https://github.com/samovers/OFARM2/pull/425) and [#422](https://github.com/samovers/OFARM2/issues/422) | The coordinator checks an earlier outcome and handles retries. On the new-attempt path it requests selection before allocation. The guard owns dispatch and finalization belongs to its manager. The writer validates and stages the claim. |

The protected assets are the farm’s chosen rules and the authority to select them for one save. Trust the signed binding, the governed database read and the independently issued package references. A caller can repeat requests, present foreign IDs or hashes, or ask for the other command. A compromised database owner, release producer or deployed program is outside this design. The main risk is mistaking equal bytes or an equal action name for the farm’s Submit choice. Save draft shares this action and permits a different outcome. [Draft command](../../contracts/candidates/temporal_governed_command/OFARM_OperationClaimDraftTemporalCommand_candidate_v0_1.json)

## Reading the choice

1. Enter `ApplicationRuntime.tenant_unit_of_work` using the ordinary app or worker login. The manager binds the principal to the database transaction. For a new attempt, #178 calls `unit.resolve_assert_operation_claim_runtime_bundle()` with no arguments. Replaying a saved result belongs to #178. [Runtime entry](../../kernel/application_runtime.py) · [Unit and manager](../../kernel/tenant_uow.py)
2. Reserve selection on this live unit before the first read. Obtain exactly one committed Submit choice through a fixed, zero-argument read on that connection. In one statement snapshot join the protected farm, its selection and activation, and the visible ledger head. Verify tenant ID and reference, selection binding ID and digest, command binding, and the activation’s batch ID, operation, bundle digest and position. Require a positive activation position at or below the observed head and absence of a batch already allocated in this transaction. A missing or ambiguous row refuses. The pre-existing activation batch is setup evidence. [Draft reader’s snapshot pattern](../../kernel/migrations/0010_tenant_command_runtime_bundle_selector.sql)
3. Compare the row’s selection ID and digest to #430’s approved selection document. Compare its command ID, binding ID, version and digest to #431’s issued tuple. From the chosen farm and bundle digest, read and reconstruct the sealed bundle. Compare its canonical bytes, member identities, lengths, placement and content digests against the admitted inventory using each owner’s digest rules. Use the output of #431’s trusted verifier for that exact package, including the dependencies used by the companion read rule. Reuse the existing immutable bundle loader. A caller-supplied digest, a passing fixture, a newer package or the draft reader cannot make these checks pass. [Bundle reconstruction](../../kernel/tenant_command_runtime_bundle_selector.py) · [Package design](https://github.com/samovers/OFARM2/pull/432)
4. Check the selected action, intent and body profiles, contract ID/version/digest and result schema identity/version/digest against the consumer agreement. The merged guard requires `ofarm.protectedeffect.assertionrecord.submit.v0.1`, version `0.1`, and `ofarm.assertionrecord.v0.2`. Its RFC names `EI_OPERATION_ASSERTION_V0_2` and `OPERATION_CLAIM_BODY_V0_2`. The version 2 package design requires typed fields the earlier schemas reject. The reviewed candidate names a different contract and result. The release owners provide the final identities. Incompatible names, bytes or meaning must refuse before allocation, even with a genuine selection and valid package. A change to this agreement needs its owners’ separate review. [Guard checks](../../kernel/tenant_claim_write_guard.py) · [Typed package and original approval scopes](https://github.com/samovers/OFARM2/pull/432)
5. Before publishing, confirm the unit is active, on its owning thread, still resolving this command, able to write, and clear of an allocating or allocated batch. Publish the full immutable binding to **one command-tagged slot**. Retain the farm, selection and command bindings, activation evidence, original ledger cut, bundle and admitted rule details. The guard’s eight-field view comes only from this value. Two independent command caches could select both commands on one transaction.

## Reading again and allocating a batch

| Situation | Required behavior |
| --- | --- |
| Same command on the same live unit, already verified, before allocation | A repeat public read returns the identical object with the original ledger cut and zero additional SQL. |
| Different command on a resolved unit, or re-entry during selection by the owner | Refuse, set rollback-only and expose no binding. A caught inner refusal cannot let the outer call publish. Exercise both command orders. |
| Allocation already started or finished | Public Submit lookup refuses before SQL, including a repeat call after allocation. A caught refusal by the owning caller prevents commit. |
| Private guard read | `_selected_assert_operation_claim_runtime_bundle()` returns the cached assertion binding only on its live, owning, resolved and unlatched unit. This includes the normal post-allocation guard read. All other states yield no binding. It performs no lookup, SQL, registration or state change. |
| Closed unit or returned lease | Public lookup on the closed unit refuses. A new unit starts empty even on the same connection or for the same farm. A foreign thread cannot mutate the owner’s choice, latch or lease through the selector. |

**Batch ordering is a transaction-owner prerequisite.** Reserve each operation on the unit before entering its underlying read or allocator. If selection has started, allocating a batch while it is checking must give zero allocator calls. If allocation started first, the public selector must give zero reader calls even while the returned batch field is still empty. The owner must arbitrate both transitions together. A foreign call must leave the owner’s state intact. An invalid same-owner overlap must make a caught failure terminal. Publishing only after a final state check protects the cache but cannot prevent an allocator that already ran. This requirement is local to one unit. Independent farms and units must remain usable. The owner can supply a synchronous ownership and in-progress check or an equivalent interface with these observable guarantees. The proposed #427 change consumes that interface. A change to admission to the general batch allocator belongs in a separate transaction-owner delivery. [Current allocation and lookup](../../kernel/tenant_uow.py#L323-L386)

**Observed on the existing unit.** We exercised both public calls on the merged unit with in-memory counters that stopped at callback entry. During a Save draft lookup, the allocator was entered once. With allocation in progress, the draft reader was entered once. Both observations ran on one thread and reached neither SQL nor a completed batch or selection. All 64 existing selector and unit-of-work tests passed. They establish the draft and transaction baseline. The Submit methods are still absent on this revision. The transaction owner can verify the ordering fix on the same two entry counters before #430 or #431 is ready.

## Current permissions

Eight focused checks passed with zero skips on disposable PostgreSQL 17.10 at main `15f2b2109c39197617fa2d7469fe412bc5a7e2d6`. Both ordinary logins used the shared runtime entry. The checks verified their actual session and current roles and the signed farm identity.

| Checked on main | App | Worker |
| --- | --- | --- |
| Resolve the activated Save draft selection for the bound farm and load its sealed bytes | Yes | Yes |
| Read a column of the stored selection table directly | Denied | Denied |
| Execute the Save draft activation routine | Denied | Denied |
| Read a Submit selection through a fixed runtime routine | No installed reader | No installed reader |
| Read the draft selection with no tenant binding | Refused | Refused |

For each role a second farm could read its own identical sealed package. Only the first farm had a choice. The second farm’s draft lookup refused, the caught refusal blocked a later batch, and normal exit reported `TRANSACTION_FAILED`. Independent observations of both farms’ selection counts, all batch counts and maximum ledger positions agreed before and after. The catalog and the fixed SQL explain why these are Save draft controls. [Role and catalog tests](../../kernel/tests/test_postgresql_tenant_command_runtime_bundle_selector.py#L283-L420) · [Function and grants](../../kernel/migrations/0010_tenant_command_runtime_bundle_selector.sql#L58-L190)

**Database access prerequisite.** The database access owner must admit a fixed Submit read for both ordinary logins, preserve denial of direct selection-table access, limit rows to the signed farm, and prove its activation linkage and effective privileges. #430’s setup login and its verifier serve the control operation. They cannot grant an ordinary session a Submit reader. #427 must refuse while that read is unavailable.

## Verification and limits

Use both ordinary session identities through the shared runtime entry point. For every pre-batch refusal on the owning unit, count allocator and writer calls from before the read and require zero. Check the unit has no batch, its private accessor is empty, and a subsequent allocation still fails after the caller catches the error. A normal exit after the caught refusal must report `TRANSACTION_FAILED`. Compare **all** batch counts, selection counts and farm ledger heads before and after using independent observers with a known visible committed row. For an intentionally preallocated batch, require rollback of that batch and zero further allocations. [Existing PostgreSQL checks](../../kernel/tests/test_postgresql_tenant_command_runtime_bundle_selector.py) · [Unit lifecycle checks](../../kernel/tests/test_tenant_uow.py)

| Case | Required evidence |
| --- | --- |
| Missing binding, missing reader permission, absent or uncommitted choice, foreign farm | Failed tenant binding yields no unit. A bound ordinary caller receives the same opaque selection refusal for a missing or invisible choice. Putting identical sealed bytes on both farms cannot turn the other farm’s choice into a local one. |
| Draft-only or conflicting details | Use the same action and bundle with the draft command. Separately vary one selection pin, activation link or position, command revision, component byte, contract digest, schema digest or package admission. Each stops before allocation. A fresh draft read still returns the original draft evidence. |
| Overlap and cache | Pause each underlying operation at its boundary and count entry calls in both orders. Exercise owner re-entry and a foreign attempt, plus an independent unit as a control. After a clean verified selection, allocating normally is allowed. Test repeat reads, both switch directions, rollback-only, closure and pooled connection reuse. |
| Genuine positive | Use an independently issued #431 package compatible with the consumer, a bundle sealed for this farm, and the selection committed through #430. Both ordinary roles must read the same activation and exact admitted rules. Reading alone must leave the batch count unchanged. When #178 wires the actual guard operation, its projection must read this unit’s cache, and an empty cache must produce zero dispatches. |

The smallest eventual implementation is the two named methods, one tagged selection state and a fixed verifier on the bound unit, with the focused unit, PostgreSQL and architecture checks. Preserve the draft pins and its read path. Keep the production writer factory closed. Database access, an allocator ordering change, package admission, activation and the first save retain their separate owners. This design is provisional. A missing zero-argument read, missing ordering guarantee or incompatible release keeps Submit unavailable and returns the affected decision to its owner before implementation relies on it.

Next, have the database and transaction owners deliver the fixed read and mutual exclusion on one unit. Then exercise the genuine positive with #430’s committed farm choice and #431’s issued, compatible package.
