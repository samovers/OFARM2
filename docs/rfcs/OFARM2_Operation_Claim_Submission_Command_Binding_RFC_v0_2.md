# Operation claim submission command binding v0.2

**Proposed for review on 18 November 2026.** Decision `OFARM2-OPERATION-CLAIM-SUBMISSION-BINDING-001`, version `2`, would bind the stable command `SUBMIT_OPERATION_CLAIM` to OFARM’s typed operation claim. The proposed OFARM2 binding ID is `ofarm.submission-command.operation-claim.v0.2`, version `0.2`. Version 1 was approved at `61d087f3c31d514dd06683c9487bd67c4ce2e935` for a different contract. Version 2 needs its own review and decision. The current result for #430 is **unavailable**. [Version 1 RFC](OFARM2_Operation_Claim_Submission_Command_Binding_RFC_v0_1.md) · [Delivery PR #432 for #431](https://github.com/samovers/OFARM2/pull/432)

## Which operation the command binds

The sole trust boundary is the OFARM2 submission-command identity and its binding to an independently admitted canonical package. The proposed effect is one immutable typed `AssertionRecord` with `assertionType=OPERATION_CLAIM_ASSERTION` and `claimState=PENDING_REVIEW`. The action is `ASSERT_OPERATION_CLAIM` at `DRAFT_PREPARATION`. Its intent uses `OPERATION_ASSERTION` and `PROSPECTIVE_TARGET_ALLOWED`, with record commit class `operation claim` and token `OPERATION_CLAIM`. The contract carries duties for one assertion, the validated bytes, the pending state and the operation branch (`PC_ONE_ASSERTION`, `PC_VALIDATED_BYTES`, `PC_PENDING_REVIEW`, `PC_OPERATION`). [Typed contract](https://github.com/samovers/OFARM/blob/180190af1f3c6cf866bbac3037df6ba1ebfbb1cf/03_machine_contracts/drafts_non_default/assertion_record_submission/complete_typed/contract.json) · [Duty graph](https://github.com/samovers/OFARM/blob/180190af1f3c6cf866bbac3037df6ba1ebfbb1cf/03_machine_contracts/drafts_non_default/assertion_record_submission/complete_typed/duty-graph.json)

`COMMIT_OPERATION_CLAIM_DRAFT` shares the action and stage. It ends in `RETAIN_DRAFT` and forbids an AssertionRecord. The checker requires the exact submission-command ID, binding version and effect. A shared action, commit-class token, attempt ID or tenant RuntimeBundle digest cannot select this command. Version 1 selected `ofarm.protectedeffect.assertionrecord.submit.v0.1`, `EI_OPERATION_ASSERTION_V0_2`, `OPERATION_CLAIM_BODY_V0_2` and `ofarm.assertionrecord.v0.2`. Its historical records keep that interpretation. Replaying the saved claim against both schema pairs showed why a separate version is needed. The typed intent and result require `claimLanguageRevision`, `proposition` and `performedByBinding`. Both older schemas reject those members even after changing the version labels. [Draft command](https://github.com/samovers/OFARM2/pull/245) · [Schema comparison and fixture](https://github.com/samovers/OFARM/blob/180190af1f3c6cf866bbac3037df6ba1ebfbb1cf/03_machine_contracts/drafts_non_default/assertion_record_submission/complete_typed/README.md#handoff-to-the-policy-package-owner)

## Admission and verification in OFARM2

The protected assets are the command identity and the digest #430 can consume. Start from a reviewed OFARM2 package entry that pins the binding file and the upstream owners’ admission records. Compare the final owner release with the frozen review inventory above, record every changed reference, and review those final bytes before the first binding is issued. A change in the approved command meaning, authority, outcome or scope requires a new decision. Once issued, any change to its package or meaning requires a new binding version. The main risk is accepting an unadmitted package or a draft command because some bytes match. Treat caller input, fixture verdicts and PR text as untrusted for admission. The checker assumes the trusted release producer and deployment are intact. [Version 1 verification rules](OFARM2_Operation_Claim_Submission_Command_Binding_RFC_v0_1.md#what-the-verifier-can-return)

One offline checker resolves both complete rule dependency sets from the pinned original bytes, including inputs used only by the read rule. It selects only the assertion for submission. Strictly decode the closed binding JSON as UTF-8 and reject duplicate or unknown members. Hash the whole document with `OFARM_CANONICAL_JSON_V1` and SHA-256, with no self-digest member. Compare both the canonical digest (`sha256:` plus lowercase hex) and original file hash with the independent package entry. Only a complete match returns `(SUBMIT_OPERATION_CLAIM, ofarm.submission-command.operation-claim.v0.2, 0.2, bindingDigest)`. Any missing, altered or unadmitted reference returns **unavailable**, identifies the reference, and yields no selectable digest. [Canonical encoding](../../kernel/runtime_bundle.py) · [Selection consumer #430](https://github.com/samovers/OFARM2/issues/430)

| Verification case for the binding checker | Required result |
| --- | --- |
| Present independently admitted original releases for every reference and repeat the check. | Both runs return the same tuple and binding digest. This positive needs the owners’ final releases. |
| Present the current #47 candidate, a v1 schema relabelled as typed, or the draft command with the same action, stage and bundle. | Unavailable. Identify the missing admission or mismatched identity or schema. |
| Change a body pointer, file byte, nested registry digest or another contract branch. Supply an internally consistent contract with a stale registry. | Unavailable. Recompute the full contract and its dependencies from the original bytes. |
| Supply an extra, duplicate or missing rule. With both rules intact, remove or alter only the `EI_DATA_READ_V0_2` schema. | Unavailable in each case. Restoring exact bytes to a fully admitted package reproduces its original tuple. |
| Substitute a passing evidence record for the policy manifest, or present the guarded-write label with a different policy checkpoint. | Unavailable. Identify the missing policy selection or incompatible profile. |
