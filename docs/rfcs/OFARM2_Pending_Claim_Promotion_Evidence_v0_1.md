# Why an operation claim entered the review queue

Design for [#428](https://github.com/samovers/OFARM2/issues/428). The primary trust boundary is **Kernel Commit Ingress promotion evidence**. On the first eligible save, a farm must be able to follow the exact pending claim back to the submission, the rule in force and the checks that allowed it into review. The sole successful write owned here is one `ofarm.promotiontrace.v0.1` and one `PROMOTION_EMITS` edge from it to the already staged claim. The claim remains `PENDING_REVIEW`. Deciding whether the reported operation happened requires a later review. [First-save design](https://github.com/samovers/OFARM2/blob/d4bf63b4e9cca90a9fd5c2f2a61b51c407b6fdef/docs/rfcs/OFARM2_Operation_Claim_Writer_RFC_v0_1.md#L7-L28) · [Kernel reachability](../../KERNEL.md#the-reachability-invariant)

### Which event the request names

If the intent associates a world event, resolve that exact revision or digest. Its independently verified Event Ingress classification must bind the original envelope **and request**, selected profile and owner context, dominant consequence, family and commit class. The trace copies the classified family only after checking equality with the envelope. Consume #422's passing subject, scope, time and body compatibility bindings to the same event. A different operation at the same farm can have the same family. Keep original source bytes available for byte-hash checks separately from canonical payload digests. [Event association](https://github.com/samovers/OFARM/blob/6c5c6eb754baecfa38b7e364fc3d0318ae1ad89f/package_meta/history/clean_baseline_migration/phase_reports/assertion_record_submission_protected_effect_contract_rfc_candidate_v0_1.md#L459-L480) · [Offline classification contract](https://github.com/samovers/OFARM/blob/2cf45bef00bcdd5e865973535646a9db8b47267d/03_machine_contracts/drafts_non_default/event_ingress_classification_proof/README.md)

If the intent has **no associated world event**, the request must already name a separately governed envelope for this submission act. Resolve it from its own provenance under the tenant binding. Require an independently selected source that identifies this act and ties it to the original submission, actor, scope and intended assertion, plus a passing classification for that envelope and request. An offline assertion-act receipt can help establish who submitted what and when. It cannot supply either the envelope or its classification. A missing source, ambiguous association, stale revision, or proof for another request ends the success path. The existing event keeps its original promotion edge. [Submission-act rule](https://github.com/samovers/OFARM/blob/6c5c6eb754baecfa38b7e364fc3d0318ae1ad89f/package_meta/history/clean_baseline_migration/phase_reports/assertion_record_submission_protected_effect_contract_rfc_candidate_v0_1.md#L478) · [Permitted transaction members](https://github.com/samovers/OFARM/blob/b1abe2c93c7ca8b7a94a11bdb0fded64bb2e75e6/package_meta/history/clean_baseline_migration/phase_reports/not_required_transaction_and_consumption_protocol_rfc_candidate_v0_1.md#L675-L692)

## One transaction and one link

1. #178 calls the private production Commit Ingress operation after the checked claim call returns and the required checkpoint passes, while finishing the gate evidence and before hashing the consumption and receipt. The tenant manager owns the original connection and finalization. The fixed producer operates on that bound backend. It accepts no caller-selected connection, gate evaluator or verdict. Check live tenant, selected bundle, request, batch and full PostgreSQL transaction ID against the staged rows and current transaction. Reuse of a closed operation or use on another transaction must fail.
2. Commit Ingress verifies those joins and constructs the review-routing decision. In the existing schema set `idempotencyDisposition = NEW_REQUEST` only from the eligible admission, `finalOutcome = REQUIRE_REVIEW` and `emittedAssertionRecordRefs = [checked assertion ID]`. Record the actual gate sequence through review routing. Use the authorization result reference and the applicable sufficiency-case reference. Gate `relatedArtifactRefs` must lead to the verified rule and owner evidence. Check those immutable references round-trip to the selected revisions and digests. The schema has no top-level rule field. Use a Kernel-assigned trace ID and trusted evaluation time, distinct from the original assertion time and any later commit, plus a summary of the queue decision. Omit review decisions, accepted consequences, materialization and in-force effects. Validate the complete trace against the pinned schema and these semantic conditions. [Trace schema](../../contracts/kernel/OFARM_PromotionTrace_schema_v0_1.json) · [Accepted trace contract](https://github.com/samovers/OFARM/blob/4a3d88ea6eff4b3f8a2c521dc621595cbfd1657b/02_accepted_rfcs/OFARM_Event_Ingress_and_Promotion_Boundary_Closure_RFC_v0_1.md#L115)
3. Stage the canonical trace and its outgoing edge as one PostgreSQL statement on that backend, with the trace insert returning the source key for the edge insert. Both carry the allocated tenant, batch and full transaction ID. Return the stored trace binding to the coordinator for inclusion in its gate evidence. Propagate insertion errors, including a second edge for the same claim. Only the original manager can commit. The coordinator must let any producer or readback failure escape the managed transaction before handling it. The merged #424 latch covers the earlier claim call. It does not wrap this later operation. [Edge checks and uniqueness](../../kernel/migrations/0001_initial.sql#L2080-L2159) · [Transaction exit](../../kernel/tenant_uow.py#L572-L595)

The protected assets are the tenant's pending assertion, its original source evidence and its unique promotion link. The primary risk is a genuine-looking trace for another submission, or a partial write surviving refusal. Trust the bound transaction, fixed production composition and independently admitted source owners. Request fields, supplied verdicts, ID strings and well-formed JSON alone are untrusted. Compromised owners, database administrators and arbitrary code execution in the deployed process are outside this design.

## What can be verified

The acceptance target is the production producer on disposable PostgreSQL under both `ofarm_app` and `ofarm_worker`. An isolated caller may use fictional input content and a separately seeded governed source. It must exercise the real producer, the actual source checks and the original tenant transaction. Preserve original bytes, schema pins and a committed same-tenant visibility control. Count **all** new traces and outgoing links in the tested batch. A named ID alone could hide an extra row.

| Case | Required result |
| --- | --- |
| Valid associated event or separately governed submission act | Inside the transaction resolve and rehash the trace and follow its sole outgoing edge to the intended staged assertion. An independent observer sees only the earlier committed inputs. After outer commit, a newly bound observer verifies the same graph, IDs, tenant, batch, full transaction ID, rule and checks. Exactly one trace and edge were added. The source event and its edge are intact. |
| Source or gate failure | Omit the envelope or classification separately. Substitute another tenant, submission, same-family event, original byte sequence, actor, rule revision or subject. Remove, reorder, duplicate or refuse an applicable gate, or claim an unsupported exemption. Each must refuse and yield zero new durable traces or edges. |
| Wrong emitted record | Substitute a different ID, digest, row kind, state, batch or full transaction ID. An otherwise schema-valid trace with a missing, duplicate or different emitted assertion, extra success effect or invented gate outcome must also fail the producer's checks. |
| Rollback and duplicate emission | Roll back after a successful return. Force the edge insert to fail, then separately attempt a second emission. Check zero new durable traces and edges after each failed transaction. Keep any pre-existing committed proof. Ordinary-role observer checks require the known visible control in every case. |
| Readback failure after both inserts succeed | In the isolated caller, run the real producer and observe the trace and edge on the writing backend. Inside the producer's readback of the stored binding, before it returns, inject a Python exception while PostgreSQL reports an active transaction (`INTRANS`). Catch it only outside the tenant manager's context. Assert the same error escaped, zero COMMIT calls, and zero new traces or edges in a freshly bound observer that can read the committed control. Repeat under each ordinary role. #178 must repeat this case through its own coordinator when it integrates the producer. |
| Reuse after transaction exit | Retain the producer after its unit closes. Attempt to use it again during a later lease, including reuse of the same physical backend. Require refusal before either insert and zero new traces or edges in the later batch. |

## Delivery limits

At main `15f2b210` the batch allocator, storage and guarded claim interface exist. Production composition still supplies an unavailable claim operation. The guard is consumed on use. It exposes no post-return promotion call. #178's trusted composition must bind the producer to the same backend and propagate failures through the outer transaction. A private caller in the isolated acceptance test can bind it the same way. Any new transaction-owner capability needed for that composition belongs to a separate prerequisite. Opening a second connection or extending the public unit in this delivery would change the agreed boundary. [Bound operation](../../kernel/tenant_uow.py#L443-L451) · [Guarded call design](OFARM2_Guarded_Operation_Claim_Call_RFC_v0_1.md#authority-and-call-order)

The production request-to-attempt binding, admitted rule, owner gate evidence and checked pending result must come from their respective deliveries. The additional gap for claims without a world event is a producer of the separately governed submission-act envelope and a trusted classification bound to it. OFARM [#48 / draft #49](https://github.com/samovers/OFARM/pull/49) verifies supplied original inputs offline. [#52 / draft #53](https://github.com/samovers/OFARM/pull/53) concerns evidence of the assertion act. Neither supplies a live submission event. A separate Event Ingress delivery would need to show a resolvable event for the exact act with independently admitted classification, and refuse a substituted act. The accepted first-save design permits the pending-claim producer to refuse this branch until then.

This is a provisional pre-deployment design. The smallest implementation is one fixed Kernel producer plus focused tests of its evidence and two writes in this same PR. The legacy M1 emitter also writes an event edge, ingress result and idempotency outcome and takes its family from its own normalization. Reusing it would grant effects owned elsewhere. [Production and legacy boundaries](../../kernel/README.md#ofarm2-kernel--production-foundation-and-legacy-m1-prototype) · [Legacy emitter](../../kernel/emission.py#L402-L438)

[#429](https://github.com/samovers/OFARM2/issues/429) owns database enforcement. #422 owns validation and writing the pending claim. #178 owns attempt admission, complete command outcome, final checks and replay. This design requires no migration, endpoint, event creation, deployment or budget transfer. Revisit the design if the admitted sources, evidence representation, permitted writes or transaction ownership change.
