# Why an operation claim entered the review queue

Design for [#428](https://github.com/samovers/OFARM2/issues/428). The primary trust boundary is **Kernel Commit Ingress promotion evidence**. On the first eligible save, a farm must be able to follow the exact pending claim back to the submission, the rule in force and the checks that allowed it into review. The sole successful write owned here is one `ofarm.promotiontrace.v0.1` and one `PROMOTION_EMITS` edge from it to the already staged claim. The claim remains `PENDING_REVIEW`. Deciding whether the reported operation happened requires a later review. [First-save design](https://github.com/samovers/OFARM2/blob/d4bf63b4e9cca90a9fd5c2f2a61b51c407b6fdef/docs/rfcs/OFARM2_Operation_Claim_Writer_RFC_v0_1.md#L7-L28) · [Kernel reachability](../../KERNEL.md#the-reachability-invariant)

### Which event the request names

If the intent associates a world event, resolve that exact revision or digest. Its independently verified Event Ingress classification must bind the original envelope **and request**, selected profile and owner context, dominant consequence, family and commit class. The trace copies the classified family only after checking equality with the envelope. Consume #422's passing subject, scope, time and body compatibility bindings to the same event. A different operation at the same farm can have the same family. Keep original source bytes available for byte-hash checks separately from canonical payload digests. [Event association](https://github.com/samovers/OFARM/blob/6c5c6eb754baecfa38b7e364fc3d0318ae1ad89f/package_meta/history/clean_baseline_migration/phase_reports/assertion_record_submission_protected_effect_contract_rfc_candidate_v0_1.md#L459-L480) · [Offline classification contract](https://github.com/samovers/OFARM/blob/2cf45bef00bcdd5e865973535646a9db8b47267d/03_machine_contracts/drafts_non_default/event_ingress_classification_proof/README.md)

If the intent has **no associated world event**, the request must already name a separately governed envelope for this submission act. Resolve it from its own provenance under the tenant binding. Require an independently selected source that identifies this act and ties it to the original submission, actor, scope and intended assertion, plus a passing classification for that envelope and request. An offline assertion-act receipt can help establish who submitted what and when. It cannot supply either the envelope or its classification. A missing source, ambiguous association, stale revision, or proof for another request ends the success path. The existing event keeps its original promotion edge. [Submission-act rule](https://github.com/samovers/OFARM/blob/6c5c6eb754baecfa38b7e364fc3d0318ae1ad89f/package_meta/history/clean_baseline_migration/phase_reports/assertion_record_submission_protected_effect_contract_rfc_candidate_v0_1.md#L478) · [Permitted transaction members](https://github.com/samovers/OFARM/blob/b1abe2c93c7ca8b7a94a11bdb0fded64bb2e75e6/package_meta/history/clean_baseline_migration/phase_reports/not_required_transaction_and_consumption_protocol_rfc_candidate_v0_1.md#L675-L692)

## Where the evidence goes in the trace

Use the existing six gate entries through review routing, in the order below. Each entry's `outcome` preserves its owner's disposition for this pending save. Store the immutable references in that entry’s `relatedArtifactRefs` array. During readback, follow the references to the checked original bytes, rule revisions and digests. Each referenced owner record must reproduce the binding for this attempt. [Trace fields](../../contracts/kernel/OFARM_PromotionTrace_schema_v0_1.json#L82-L175) · [Gate owners and order](../../reference/law/OFARM_Platform_Runtime_and_Product_Architecture_RC2_1.md#L80-L136)

| Gate | What its references must identify |
| --- | --- |
| `INGRESS_NORMALIZATION` | The original normalized ingress request binding and the independent Event Ingress proof for its exact request and envelope bytes. The trace's `requestId` and `semanticEventRef` name those same objects. Its `primaryEventFamily` equals the verified family. |
| `AUTHORITY` | The consumable `ALLOW` result, its full authorization trace, and the immutable rule or manifest binding through which the selected policy, rule revision and digest resolve. Set `authorizationDecisionResultRef` to this same result ID. |
| `VALIDATION` | #422's passing protected-effect validation trace. Its domain payload must resolve and match the returned payload digest, admitted intent, contract, result schema and exact staged assertion. |
| `PACK_PROFILE_APPLICABILITY` | The owner's applicability decision and the selected pack/profile context that identifies the rules and evidence policy in force for this submission. |
| `EVIDENCE_SUFFICIENCY` | For an applicable check, reference the owner's decision and its case. Set `evidenceSufficiencyCaseRef` to that case's ID. Preserve a review disposition only if the policy expressly permits saving this claim as pending. For an actual exemption, record `NOT_APPLICABLE` with the immutable applicability basis and omit the case reference. Missing or refused required evidence prevents the save. [Evidence dispositions](https://github.com/samovers/OFARM/blob/4a3d88ea6eff4b3f8a2c521dc621595cbfd1657b/01_companion_artifacts/OFARM_Evidence_Sufficiency_and_Attestation_Policy_v0_1.md#L95-L106) |
| `REVIEW_PROMOTION` | Record the established queue disposition `REQUIRE_REVIEW` and reference the checked pending assertion. Its ID must equal the sole member of `emittedAssertionRecordRefs` and the destination of the sole outgoing promotion edge. |

## One transaction and one link

1. #178 selects the owner-guarded production path before staging a claim. If the transaction owner cannot supply that path, first-save dispatch stays unavailable. After #422's checked return and the required checkpoint, #178 calls Commit Ingress to finish the evidence for the completed gates, before hashing the consumption and receipt. The producer receives the original tenant, selected bundle, request, batch and full PostgreSQL transaction ID on the same physical lease. It checks these against the live unit and staged rows. [First-save order](https://github.com/samovers/OFARM/blob/b1abe2c93c7ca8b7a94a11bdb0fded64bb2e75e6/package_meta/history/clean_baseline_migration/phase_reports/not_required_transaction_and_consumption_protocol_rfc_candidate_v0_1.md#L657-L674)
2. Verify all source bindings and construct the six gate entries. Set `idempotencyDisposition = NEW_REQUEST` from the eligible admission and `finalOutcome = REQUIRE_REVIEW`. Supply a Kernel-assigned trace ID, trusted evaluation time and summary. Omit review decisions, accepted consequences, materialization, publication and in-force effects. Validate the complete trace against the pinned schema and the semantic conditions above. [Accepted trace contract](https://github.com/samovers/OFARM/blob/4a3d88ea6eff4b3f8a2c521dc621595cbfd1657b/02_accepted_rfcs/OFARM_Event_Ingress_and_Promotion_Boundary_Closure_RFC_v0_1.md#L115)
3. Insert the canonical trace and its edge in one statement on that backend. Use the inserted trace key as the edge source. Resolve the stored trace and edge, check their tenant, batch, full transaction ID, exact references and digests, and compare the returned trace binding to the expected ID and digest **inside the guarded call**, before #178 can treat it as successful. Only a checked success returns the stored trace binding to #178. The original manager alone finalizes. [Edge checks and uniqueness](../../kernel/migrations/0001_initial.sql#L2080-L2159)

### A caught failure must prevent commit

The transaction owner must provide one fixed, single-use call that encloses steps 2 and 3 and the live owning unit's input checks in step 1. The caller cannot invoke the bound producer directly, select its callback, or obtain a SQL handle. Once the calling lease and thread are established, **any** failure in that call, before or after either insert, must set the owning unit's existing rollback-only flag before re-raising the original exception. This includes a refused binding, a database error, an invalid return, and any Python `BaseException` during readback. Repeated or re-entrant calls on that live unit also fail closed. A stale handle or foreign thread is refused before dispatch and cannot affect a different live unit. [Ownership pattern in the merged claim guard](../../kernel/tenant_uow.py#L339-L354)

The caller may catch the error **inside** the tenant block and exit normally. The flag still prevents a COMMIT attempt, even if PostgreSQL reports `INTRANS` or a savepoint restored that status. The existing manager rolls back or discards the connection and reports `TRANSACTION_FAILED` on normal exit. An exception that leaves the block follows its existing rollback path. Finalization uncertainty and retry decisions remain with their owners. Issuing a second, deliberately failing SQL statement cannot guarantee this invariant if that statement never reaches the backend or a savepoint clears its error. [Manager exit](../../kernel/tenant_uow.py#L572-L595) · [Rollback-only contract](OFARM2_Tenant_Transaction_Failure_Handling_RFC_v0_1.md#permitted-effects-and-explicit-compatibility-change)

The protected assets are the tenant's pending assertion, its original source evidence and its unique promotion link. The primary risk is a genuine-looking trace for another submission, or a partial write surviving refusal. Trust the bound transaction, fixed production composition and independently admitted source owners. Request fields, supplied verdicts, ID strings and well-formed JSON alone are untrusted. Compromised owners, database administrators and arbitrary code execution in the deployed process are outside this design.

## What can be verified

The acceptance target is the production producer on disposable PostgreSQL under both `ofarm_app` and `ofarm_worker`. An isolated caller may use fictional input content and a separately seeded governed source. It must exercise the real producer, the actual source checks and the original tenant transaction. Preserve original bytes, schema pins and a committed same-tenant visibility control. Count **all** new traces and outgoing links in the tested batch. A named ID alone could hide an extra row.

| Case | Required result |
| --- | --- |
| Valid associated event or separately governed submission act | Inside the transaction resolve and rehash the trace and follow its sole outgoing edge to the intended staged assertion. An independent observer sees only the earlier committed inputs. After outer commit, a newly bound observer verifies the same graph, IDs, tenant, batch, full transaction ID, rule and checks. Exactly one trace and edge were added. The source event and its edge are intact. |
| Source or gate failure | Omit the envelope or classification separately. Substitute another tenant, submission, same-family event, original byte sequence, actor, rule revision or subject. Remove, reorder, duplicate or refuse an applicable gate, or claim an unsupported exemption. Each must refuse and yield zero new durable traces or edges. |
| Wrong emitted record | Substitute a different ID, digest, row kind, state, batch or full transaction ID. An otherwise schema-valid trace with a missing, duplicate or different emitted assertion, extra success effect or invented gate outcome must also fail the producer's checks. |
| Rollback and duplicate emission | Roll back after a successful return. Force the edge insert to fail, then separately attempt a second emission. Check zero new durable traces and edges after each failed transaction. Keep any pre-existing committed proof. Ordinary-role observer checks require the known visible control in every case. |
| Refusal before the first proof insert, caught by the caller | With the claim already staged, supply a missing required classification or a refused gate. Catch the producer refusal **inside** the managed block and exit normally. For each role require `TRANSACTION_FAILED`, zero native COMMIT calls, and a fresh bound observer that sees its control and counts zero new claims, traces and promotion edges in this batch. |
| Readback failure after both inserts, caught by the caller | In separate runs under `ofarm_app` and `ofarm_worker`, let the real producer stage the trace and edge. Verify both on the original backend and verify a second same-role connection can see the committed control and none of this batch’s new rows. During the final readback, while PostgreSQL reports `INTRANS`, inject a Python exception before the checked return. Catch that same exception **inside** the managed block and exit normally. The outer call must report `TRANSACTION_FAILED` and make zero native COMMIT calls. A freshly bound same-role observer must see the committed control and zero new claims, traces or promotion edges for this batch. Repeat the caught-error case with a real SQL error. In a savepoint variant, restore the backend to `INTRANS` after the SQL error while an earlier staged row remains visible on it. The same zero-commit and observer checks still apply. #178 repeats the post-insert Python case through its production coordinator. |
| Evidence stored in the wrong place | Use a valid rule revision or classification proof from another request, swap the normalization and authorization references, or give an applicable sufficiency case a different top-level ID. Producer verification must refuse a checked return and leave zero new proof. On a genuine policy exemption the basis resolves and the case field is absent. |
| Reuse after transaction exit | Retain the producer's guarded handle after its unit closes. Attempt to use it again during a later lease, including reuse of the same physical backend. Require refusal before either insert, zero new proof from that call and a healthy later unit that can still complete its own work. |

## Delivery limits

[#178](https://github.com/samovers/OFARM2/issues/178) owns production composition and the call after the checked claim returns. The separate **tenant transaction owner prerequisite** is a guarded promotion call through final readback on the original lease. The existing #424 guard ends before that call, and the manager at base `15f2b210` exposes no such operation. This prerequisite must supply and test the terminal rollback-only behavior before #428's ordinary-role acceptance can pass. The isolated #428 caller also has to use that real guard. A fixture marker can establish the transaction owner's behavior in isolation. It cannot satisfy the producer's acceptance tests. The manager, its public surface and its failure state belong to that separate delivery. [Existing factory](../../kernel/tenant_uow.py#L443-L451) · [Ownership and call order](OFARM2_Guarded_Operation_Claim_Call_RFC_v0_1.md#authority-and-call-order)

The production request-to-attempt binding, admitted rule, owner gate evidence and checked pending result must come from their respective deliveries. The additional gap for claims without a world event is a producer of the separately governed submission-act envelope and a trusted classification bound to it. OFARM [#48 / draft #49](https://github.com/samovers/OFARM/pull/49) verifies supplied original inputs offline. [#52 / draft #53](https://github.com/samovers/OFARM/pull/53) concerns evidence of the assertion act. Neither supplies a live submission event. A separate Event Ingress delivery would need to show a resolvable event for the exact act with independently admitted classification, and refuse a substituted act. The accepted first-save design permits the pending-claim producer to refuse this branch until then.

This is a provisional pre-deployment design. The smallest implementation in this PR is one fixed Kernel producer plus focused tests of its evidence and two writes through the transaction owner’s guarded call. The legacy M1 emitter also writes an event edge, ingress result and idempotency outcome and takes its family from its own normalization. Reusing it would grant effects owned elsewhere. [Production and legacy boundaries](../../kernel/README.md#ofarm2-kernel--production-foundation-and-legacy-m1-prototype) · [Legacy emitter](../../kernel/emission.py#L402-L438)

[#429](https://github.com/samovers/OFARM2/issues/429) owns database enforcement. #422 owns validation and writing the pending claim. #178 owns attempt admission, complete command outcome, final checks and replay. This design requires no migration, endpoint, event creation, deployment or budget transfer. Revisit the design if the admitted sources, evidence representation, permitted writes or transaction ownership change.
