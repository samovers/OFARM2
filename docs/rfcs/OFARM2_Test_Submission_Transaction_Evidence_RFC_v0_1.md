# Capture the evidence for one test operation claim

Decision `OFARM2-TEST-SUBMISSION-TRANSACTION-EVIDENCE-001`, version 1, proposed for [OFARM2 #440](https://github.com/samovers/OFARM2/issues/440). The primary trust boundary is **transaction and history evidence for proposed state**. One fictional submission of `SUBMIT_OPERATION_CLAIM` needs an independently selected record of the original assertion act, authorization decision, protected observations and proposed pending assertion. A reviewer must be able to give the same bytes to the same verifier and reproduce its verdict. This PR owns that test capability.

## Who can establish each fact

| Owner | Fact and permitted action |
| --- | --- |
| Isolated conformance setup | Select one fictional tenant, test attempt, storage owner, persistence boundary, guard policy and source revisions. Before evaluating the submission, retain the selection bytes and SHA-256 independently of the offered proof. Load only fictional owner-issued test inputs obtained through their fixture interfaces. The setup controls every writer to the disposable data. |
| Tenant transaction manager | Bind the unit, thread, tenant, physical backend and lifetime. The collector reads through a private handle on that lease. The database supplies the observed versions, existence, membership and lock lifetime. Each assertion ID belongs to a single tenant namespace. |
| Assertion-act and authorization owners | Issue the test act and selected decision respectively. Their existing checkers interpret the original bytes. The collector preserves their content, rendered bytes, evidence, source records, schemas and context pins. It cannot choose an authorization result or sign for a principal. [Assertion act](https://github.com/samovers/OFARM/pull/53) · [Authorization](https://github.com/samovers/OFARM/pull/56) |
| Protected-state and domain owners | The protected-state checker verifies the supplied context, policy, proof and snapshot. The domain verifier derives the required inputs from the claim and evaluates the typed intent and resulting AssertionRecord. Each owns its own findings. [Protected state](https://github.com/samovers/OFARM/pull/51) · [Domain verifier](https://github.com/samovers/OFARM/pull/47) |
| Submission binding and command owners | [#432](https://github.com/samovers/OFARM2/pull/432) may inspect the report. Package admission, trusted runtime selection, the durable claim writer and command finalization remain with [#430](https://github.com/samovers/OFARM2/issues/430), [#427](https://github.com/samovers/OFARM2/issues/427), [#422](https://github.com/samovers/OFARM2/issues/422) and [#178](https://github.com/samovers/OFARM2/issues/178). |

The protected assets are the original owner bytes, their tenant and attempt identity, and the truth of every claimed storage observation. Request parameters, hashes accompanying an offered document, a caller-provided report and a later database query are untrusted as selection sources. The primary risk is certifying another attempt's evidence, or a changeable read, as protected in this attempt. Contain it by preselecting the sources outside the request, reading the actual bytes and guards on one open lease, and recording a refusal for each mismatch or unavailable fact. Compromise of PostgreSQL, the isolated setup or an upstream owner is outside the test model.

## One attempt, in order

1. On a fresh disposable database, select the exact contract and source revisions, including the typed intent and proposed result bytes. Pin the sources by logical identity, revision and raw SHA-256. Check that the intent, accountable party, act, authorization result and action agree. Repeated uses of one source retain their individual roles. Use original byte buffers throughout. Store a separate RFC 8785 digest only where the owner contract calls for one. The protected-state contract selects its own contract digest convention.
2. Establish the fixture's protection before the first observation that claims transaction-start availability. Use pre-existing, tenant-scoped guard keys for source rows, absent assertion IDs and relevant sets. The fixture controller holds shared protection over the selected keys before the manager opens its transaction. Transfer continuous coverage by acquiring compatible transaction-scoped protection on the bound backend before releasing the controller's locks. Every fixture writer of a guarded fact must take the corresponding conflicting lock before changing it. Make the mapping from facts and membership predicates to guard keys part of the independently selected test policy. Prove overlap and exclusion with an independent connection. For any input without demonstrated start coverage, record the actual observation time and report the required start fact as unavailable.
3. Capture the act and authorization inputs, the proposed result and the immutable originals needed by this submission. Read exact bytes and revisions from the selected tenant on the bound backend. Record each positive key/value, negative predicate and membership predicate with its exact scope, observed version or version anchor, protection and observation point. Recompute ordered member identities and digests as the selected owner contract requires. Record source absences as observed absences. A query returning zero rows alone gives no exclusion over a future insert. A full PostgreSQL transaction ID identifies a transaction and cannot establish a storage-owner selection or transaction-start snapshot.
4. Before calling the domain verifier, capture the absence of the exact proposed assertion ID and exactly one **proposed** insert tied to those same result bytes. Assemble the test source's original context, guard policy, proof and snapshot from observations and compare their selected roles and byte pins against the independent attempt record. Use [#51's pinned contract](https://github.com/samovers/OFARM/blob/538d04075881b885ed370d14326acfab7aaf429e/03_machine_contracts/drafts_non_default/authorization_finalization_evidence/protected_state_evidence/contract.json). The controller fixes the expected roles and source revisions first. When the storage observer issues the four attempt artifacts, it deposits their exact bytes once in a test-owned, read-only handoff for this attempt. A second reader retrieves the stored pins by that prior selection before inspecting any caller-offered copies. The draft proof cannot select itself. An incomplete capture identifies the missing original, version, protection or authority explicitly.
5. Seal the observed inputs for offline replay. Close the handle with its unit. Preserve the attempt's finalization and the verifier's status separately. An abort invalidates any success handoff. An unknown finalization stays unknown. The test may retain a clearly labelled diagnostic record. The only product of this PR is fictional conformance evidence. The collector never inserts a pending claim.
6. Run the existing owner checkers and replay the exact selected intent, result and owner inputs through the public [#47 verifier at `a343920`](https://github.com/samovers/OFARM/tree/a343920df53a7a85aecd6ec910c644fe245f5dc6/04_implementation_and_conformance/conformance_runners/complete_typed_assertion). Report the actual payload and validation trace, or their absence and the owning unmet gates. At this revision the manifest is incomplete and blocks a passing public payload. Eligibility rules for evidence use, package approval and later promotion evidence cannot be supplied by the collector.

## Scope and verification

Keep the collector and its test composition private to the disposable conformance path. Reuse the existing manager's binding and finalization, existing fixture roles and the published checker entry points. Prefer the private fixture composition already exercised by the [guard tests](../../kernel/tests/test_postgresql_tenant_claim_write_guard.py). The public unit has no raw connection, collector injection or typed submission route. The production guard selects the earlier result schema. Relabelling a save-draft or calling that guard with a typed test selection would invalidate the evidence. Expected changes after approval are the focused test-only collector, its fictional inputs, PostgreSQL tests and replay instructions. Any mechanically necessary reachability check can live with the existing architecture checker. A file-only replay misses the database observations. A new production producer, registry, schema, grant, migration or user-facing API would introduce separate authority.

| Invariant | Falsifiable check |
| --- | --- |
| Only this tenant's open attempt can contribute evidence | Run the PostgreSQL harness under the ordinary role with a second tenant using identical bytes and IDs. Swap tenant, attempt, lease, source revision or nonce, try a closed unit and a foreign thread. Require refusal and zero accepted handoffs. Exercise application and worker composition outside the test harness and confirm the collector is unreachable. |
| Source originals and proposed result are fixed before the verifier runs | Preserve the independent selection across the replay. Substitute a reserialized original with the same JSON meaning, a different authorization result, a stale revision and a different proposed write. Require a specific mismatch for each. Test the public domain checker with an offered verdict in place of originals. |
| Every claimed protected predicate has a matching observed guard and version | A second connection tries to revise an existing source, insert the absent ID and change the selected membership while capture is open. Observe that PostgreSQL reports the owning blocker and that the changes can proceed after release. Also run an unprotected absence or membership read and require an incomplete result. Compare independently required predicates with observed ones, including omissions and extras. |
| The test has one proposed write and faithfully reports its outcome | Observe one proposed insert with the returned test ID and matching raw/result digest. Use a fresh observer after rollback to count zero claims. Inject failure after capture and before handoff. Require zero successful submissions, even when the error is caught. Use a fresh attempt for the next run. |
| Only the owner verifier can return a passing domain payload and trace | Run all applicable owner checkers and #47 on the captured bytes, preserve the input and report hashes, and compare a second offline replay. Record an unavailable field as such. A changed digest, a missing owner input or a supplied PASS cannot produce a passing handoff. |

The task user approves this design and any change to its capability, boundary, authority, effects, invariants, named PR or deployment posture. The reviewer checks the design and implementation, CI records the required checks, and GitHub controls merge. Development is provisional and limited to this test. If a truthful observation requires a new storage authority, a production lock protocol, a domain rule or a different finalization contract, identify its owner and seek a separate decision before changing it.

The approved implementation runs on the isolated test manager at PostgreSQL tenant migration 12. The test setup selects the assertion ID before submission. The tenant backend writes the observation only to test custody. It never executes the proposed insertion into the tenant ledger. The protected keys use a cooperating fixture writer protocol under `READ COMMITTED`. The fixture and its replay instructions record the original inputs and the remaining domain dependencies.
