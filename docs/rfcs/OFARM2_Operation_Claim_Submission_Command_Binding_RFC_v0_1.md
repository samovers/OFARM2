# Operation claim submission command binding v0.1

Phase A proposal for [OFARM2 #431](https://github.com/samovers/OFARM2/issues/431). The proposed decision is `OFARM2-OPERATION-CLAIM-SUBMISSION-BINDING-001`, version `1`. The primary trust boundary is the identity of one OFARM2 submission command and its binding to an admitted canonical package. The intended delivery is one versioned binding and a read-only conformance check for [#430](https://github.com/samovers/OFARM2/issues/430).

## Proposed identity and effect

| Item | Proposed value |
| --- | --- |
| Stable OFARM2 command ID | `SUBMIT_OPERATION_CLAIM` |
| OFARM2 binding ID and version | `ofarm.submission-command.operation-claim.v0.1`, version `0.1` |
| Canonical action and stage | `ASSERT_OPERATION_CLAIM`, `DRAFT_PREPARATION` |
| Authorized intent and body | `EI_OPERATION_ASSERTION_V0_2`, `OPERATION_CLAIM_BODY_V0_2` |
| Protected effect | `ofarm.protectedeffect.assertionrecord.submit.v0.1`, version `0.1` |
| Successful domain result | One immutable operation branch of `ofarm.assertionrecord.v0.2`, with `assertionType=OPERATION_CLAIM_ASSERTION` and `claimState=PENDING_REVIEW` |

`SUBMIT_OPERATION_CLAIM` names the operation across attempts and tenants. #178 owns the identity of each attempt and its saved result. `COMMIT_OPERATION_CLAIM_DRAFT` already uses this action and stage. Its successful outcome is `RETAIN_DRAFT` and its batch forbids an AssertionRecord. Keep that existing command, schema and binding intact. The action, stage, commit-class token `OPERATION_CLAIM`, contract ID, logical operation ID and tenant RuntimeBundle digest each identify something different. None can supply the command ID. ## What the verifier can return

1. Start from the reviewed, fixed OFARM2 package entry for this command and binding version. It pins the exact local artifact and the canonical owner release and admission records to which #431 is allowed to bind. Those admission records must be traceable to the owning decisions and name the same immutable revisions and digests being tested. The closure includes the policy manifest, both resolved rules and every dependency required by either. The test subject may supply bytes for comparison. It cannot supply the trusted pins, authority to admit them, an alternate policy or a replacement resolver. Use local, provenance-verified package inputs. No lookup of a latest version or caller-selected source.
2. Require the exact command ID, binding ID, version, action and result mapping. Resolve the admitted `AuthorizationPolicyBundle v0.2` by its immutable identity, revision and digest. Its admitted action set and the set of resolved rule actions must each equal exactly `{ASSERT_OPERATION_CLAIM, RECEIVE_READ_DATA}`, with one rule per action. Reject missing, duplicate or extra entries. For **both** rules, verify the `ruleId`, `ruleRevision` and `ruleDigest` and resolve every required transitive reference to its original bytes. Recompute and compare each digest using the owning contract's projection, including references used exclusively by the read rule. Shared references can be checked once. Only after both closures pass may the verifier select the assertion rule. Its decision validity policy must select the guarded-write checkpoint and pin the exact compatible `TRANSACTION_BOUND_V0_2`, `NOT_REQUIRED`, `SINGLE_USE` transaction profile. Checking the read rule's source integrity grants no authority to evaluate a read or disclose data. [Policy scope and dependencies](https://github.com/samovers/OFARM/blob/d1178fe07d57accedde5748672602db38346b3e6/package_meta/history/clean_baseline_migration/phase_reports/authorization_constraints_and_decision_evidence_rfc_candidate_v0_2.md#L416-L426) · [Resolved rule and transaction profile](https://github.com/samovers/OFARM/blob/d1178fe07d57accedde5748672602db38346b3e6/package_meta/history/clean_baseline_migration/phase_reports/authorization_constraints_and_decision_evidence_rfc_candidate_v0_2.md#L452-L505)
3. Follow the rule to its complete protected-effect contract and to the exact intent, body, result schema, validator and validation-trace references selected by the owners. For a body selected by JSON Pointer, bind both the containing schema's identity/version/digest and the exact pointer. Verify the operation branch and the one pending-result postcondition in the table. Preserve the full contract, including its other branches. #431 checks these references and meanings. The canonical domain verifier owns the validation of an individual claim. [Protected-effect contract](https://github.com/samovers/OFARM/blob/6c5c6eb754baecfa38b7e364fc3d0318ae1ad89f/package_meta/history/clean_baseline_migration/phase_reports/assertion_record_submission_protected_effect_contract_rfc_candidate_v0_1.md#L429-L453)
4. Only a complete match returns the verified command ID, binding ID, version and canonical binding digest for #430 to pin. Missing approval or a missing, ambiguous, altered, wrong-version or non-admitted reference returns **unavailable**, with the offending reference and no usable digest. Both outcomes are read-only. The checker cannot select or activate a tenant bundle, allocate a batch, dispatch a writer, change canonical admission or confer production access. #430 owns activation, #427 owns transaction-local selection, #422 owns persistence and validation evidence, and #178 owns replay. [Selection-control boundary](https://github.com/samovers/OFARM2/issues/430) · [Writer boundary](https://github.com/samovers/OFARM2/pull/423)

### What is hashed

Keep the binding digest **outside** the binding document in the reviewed OFARM2 package pin. The input is the whole, closed, versioned JSON object, including the command identity, effect mapping and immutable owner references. It has no self-digest field. Strictly decode UTF-8 and reject duplicate or unknown fields. Use the existing OFARM2 `OFARM_CANONICAL_JSON_V1` encoding and compute `sha256:` followed by the lowercase SHA-256 of those canonical bytes. Check the exact file SHA-256 against its independently pinned package entry as well. Reformatting alone preserves the canonical digest but changes the file digest. Never borrow the digest of this RFC, a candidate schema, the draft binding, a file containing only the identity, or the tenant bundle. Once a binding version is published its content is immutable. A change to its bound package or meaning requires another binding version. [OFARM2 canonical encoding](../../kernel/runtime_bundle.py)

Each upstream digest keeps its owner's projection. In particular, the canonical `contractDigest` hashes RFC 8785 bytes of the complete materialized protected-effect contract, removing only the top-level `contractDigest` member. A schema file hash, an extracted body fragment or the approval of a source document cannot fill this field. [Digest definitions](https://github.com/samovers/OFARM/blob/6c5c6eb754baecfa38b7e364fc3d0318ae1ad89f/package_meta/history/clean_baseline_migration/phase_reports/assertion_record_submission_protected_effect_contract_rfc_candidate_v0_1.md#L600-L606)

## Trust and verification

The assets are the submission identity and the pins #430 may trust. The principal risk is accepting a draft operation or an authentic but unadmitted package by matching an action name or a digest shared with another command. The trusted inputs are the fixed OFARM2 package pin and the independently accepted upstream records. Treat application and worker payloads, local examples, PR text and status fields inside a presented package as untrusted for admission. Compromise of the trusted release producer or deployment is outside this boundary. The future selection controller has a single exact binding to check. This PR gives it no path to mutate a tenant.

| Case at the #430 handoff | Expected observation |
| --- | --- |
| All exact references, independently admitted, with original bytes | One verified tuple. Repeating the check gives the same tuple and independently reproduced canonical digest. |
| Draft command carrying the same action and stage, even with identical bundle bytes | Refuse the command identity before accepting a digest. The genuine draft still passes its own existing checks. |
| Caller supplies an action, contract ID, logical operation ID, alternative command or a different binding/result revision | Refuse exact identity or mapping mismatch. |
| Bytes are changed under a retained reference, replaced by an unknown field or duplicate key, or a raw file hash is used in the wrong digest field | Refuse integrity, schema or owner-digest mismatch. |
| Package is genuinely published but non-default, incomplete or unadmitted, or omits the read rule or the selected transaction dependency | Return unavailable with the missing input, including when the supplied package declares itself approved. |
| Start with the genuine admitted package. Keep the manifest, both rule records and every assertion input exact. Remove the read-only `EI_DATA_READ_V0_2` schema, then separately change its bytes under the original reference. | The same submission verifier names that read-only reference and returns unavailable with no usable binding digest in both cases. Restoring the exact bytes reproduces the original tuple. |
| Complete-looking contract has only a copied PASS or component hashes, or owner admission applies to another revision | Refuse that reference. Across all refusals the checker yields no selectable digest or durable effect. |

The smallest complete change is the versioned artifact, one verifier, the package entry it consumes and focused conformance in this PR. Reuse the existing strict JSON and SHA-256 functions and the canonical owners' validators. The candidate area, conformance tests, manifest and this RFC are the expected repository areas. A second policy evaluator or an activation-specific copy of the rules would duplicate authority. Phase A contains the design only. Once inputs are available, run the acceptance matrix against the same verifier, including the genuine admitted positive. The package self-check, implementation review and normal evidence gates still apply. [Conformance procedure](../../conformance/CONFORMANCE.md)

This is a provisional local development design. The task user owns the semantic decision for this PR. Verified values may fill the specified references only when they preserve this decision. A changed capability, authority, boundary, allowed or excluded effect, invariant, irreversible behavior, named PR or deployment posture requires a new decision version and approval. Canonical admission, isolated actual-path construction and its test-only consumption approval, production extraction, deployment and merge each retain their existing authorities.
