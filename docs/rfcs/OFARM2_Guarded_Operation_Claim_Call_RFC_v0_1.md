# Guarded operation-claim call on the tenant transaction

Phase A for [#424](https://github.com/samovers/OFARM2/issues/424). The primary trust boundary is **tenant transaction ownership and finalization**. Give [#178](https://github.com/samovers/OFARM2/issues/178) one synchronous call, `TenantUnitOfWork.stage_operation_claim(attempt)`, on an already bound unit. A successful return makes staged data available to its caller on that transaction. Only the existing manager can make it durable. [Current transaction manager](../../kernel/tenant_uow.py) · [Failure handling](OFARM2_Tenant_Transaction_Failure_Handling_RFC_v0_1.md)

The primary risk is committing a partial write when the caller catches a Python error after an insert. Keep dispatch **and verification of its return** inside the existing rollback-only protection. The protected assets are the tenant's transaction, pending claim and evidence. Trust the tenant binder, fixed deployment composition and each owner's verified inputs. Treat request fields, supplied IDs, verdicts and callbacks as untrusted. Database administrators, compromised deployed code and arbitrary in-process reflection are outside this model.

## Authority and call order

| Owner | Responsibility |
| --- | --- |
| #178 command coordinator | Checks the saved result under the uniqueness guard. It alone decides new attempt, old admission or replay, binds the authorized intent and expected result ID, and supplies the protected inputs. On replay it uses the saved-result path with zero writer calls. It requests command selection and schedules the remaining gates, consumption, original result and receipt before leaving the transaction. |
| [#427 tenant command selector](https://github.com/samovers/OFARM2/issues/427) | Resolves the fixed assertion command after tenant binding and **before** batch allocation. Owns both the selection authority and its per-unit cache. A selected rule binds `ASSERT_OPERATION_CLAIM`, `ofarm.protectedeffect.assertionrecord.submit.v0.1` version `0.1`, its admitted digest and result `ofarm.assertionrecord.v0.2`. The intent and body profiles are `EI_OPERATION_ASSERTION_V0_2` and `OPERATION_CLAIM_BODY_V0_2`. Those names alone confer no admission. |
| #424 tenant transaction manager | Owns the active unit and its execution thread, bound tenant, allocated batch, full transaction ID, one dispatch, rollback-only latch and finalization. It compares the observed binding with the attempt and selected command. Domain evidence and attempt history have their own owners. |
| [#422 assertion-domain writer](https://github.com/samovers/OFARM2/issues/422) | Validates and stages the assertion, its protected-effect validation trace and that trace's domain payload. Supplies typed readback of all three on the same backend. |
| [#428 Kernel Commit Ingress](https://github.com/samovers/OFARM2/issues/428) | Produces its own promotion trace and matching edge from the actual gates **after** the guarded return. The promotion trace belongs to the complete command transaction. |

**Selection.** #427 owns the public `resolve_assert_operation_claim_runtime_bundle()` and private `_selected_assert_operation_claim_runtime_bundle()` on the unit. The latter reads the resolved assertion binding from this unit’s cache without SQL. In every other selection state it yields no binding. Main's `resolve_commit_operation_claim_draft_runtime_bundle()` is fixed to a different command whose batch excludes assertions. #424 adds only the public claim-staging method. Its private bound operation exposes `selected_claim_command()`, a read-only projection of #427's accessor. It contains the tenant, action, bundle digest and selected contract/version/digest and result schema. The guard holds no second selection cache. Until the required owners are wired, the production manager supplies an unavailable operation. [Existing selector](../../kernel/tenant_command_runtime_bundle_selector.py) · [Draft batch membership](OFARM_Operation_Claim_Draft_Temporal_Command_RFC_v0_1.md#durable-batch)

**Dispatch.** The receiver and its private operation share the same live unit and physical lease. Compare the typed attempt's tenant and binding nonce with the manager's captured binding, and its batch ID, full transaction ID, action and bundle digest with the allocated batch and the cached command. Require the exact selected contract and result binding. The attempt is a value. An equal copy on the same unit is valid. Identity, attempt age, prior use of a caller key and authority for the proposed assertion ID cannot be established by copying or comparing these fields. #178 checks those facts before calling. A batch operation string alone cannot open the call.

**Return.** The manager invokes one fixed, transaction-bound `stage_and_verify_operation_claim(attempt)` operation. In production, #178's adapter calls #422 to stage, uses #422's typed readback for the staged assertion, **protected-effect validation trace** and domain payload, then calls its single `verify_staged_claim_result` check. #178 compares the actual subject and ID with the authorized intent, then builds the first passing result binding from the staged bytes and owner evidence. If a prior admitted binding exists, the entire binding must also match it exactly, including the result-schema ref/version/digest, complete result digest, contract ref/digest and validation-trace ref/digest. The adapter resolves and rehashes the domain payload referenced by that trace. #422 owns domain verification. The adapter returns the checked typed result with those claim and validation-evidence bindings. The guard requires the expected checked-result type before it returns, and catches failures from the entire operation. Kernel Commit Ingress's later promotion trace cannot be an input to this check. The fixed composition depends on the transaction interface, #178 adapter and #422 domain operations. The adapter can use the guard's value types and call #422. The guard imports neither owner and opens no storage or SQL interface to callers. ## Call states and failure handling

The manager creates an **available** guard per live unit. Only the thread that entered the synchronous manager context can dispatch. Use the owning thread object’s identity. A retained unit can be handed to another thread even while the owner is executing the `with` block. Relying on callers to keep it private would allow concurrent use of the same lease. The supported production context enters and exits on its owning thread.

| From and event | Result |
| --- | --- |
| Closed unit, or a call from another thread | Refuse before access to the bound operation, SQL or mutation of the owning unit. A returned lease stays inaccessible. |
| Live owner and existing rollback-only latch, including after a terminal selector refusal | Refuse with zero dispatches and keep the latch set. |
| Available and the fixed projection yields no assertion binding | Refuse before staging, set the latch on the active unit and perform no new lookup. #427 owns the underlying selector states. |
| Available and operation absent, input malformed, selected binding wrong, or batch missing or mismatched | Refuse before staging and set the latch. An error while reading the cached projection also sets it. |
| Available and all checks pass | Reserve the call as **in progress** before invoking any owner operation that can stage bytes. |
| In progress and called again by the owner, or **used** and called again | Refuse, set the latch and never dispatch again. Before yielding success, the outer call rechecks the latch even if the nested refusal was caught. |
| In progress and dispatch, readback, return check or result type fails | Catch `BaseException`, set the latch before propagating the original error and prohibit another dispatch. A domain refusal uses the same failure path. |
| In progress and checked return with latch clear | Mark **used** and return the provisional result. #178 can now finish the remaining gates and save the complete result within the outer transaction. |
| Manager exits | `_finish()` closes the guard and drops its bound operation before release. An escaping body error rolls back and propagates. On normal exit a latched unit yields `TRANSACTION_FAILED`, including when PostgreSQL is still `INTRANS`. A clean exit uses existing finalization. An uncertain COMMIT yields `FINALIZATION_UNKNOWN` with the existing observation path and zero automatic retries. |

## PostgreSQL acceptance for #424

Use the real tenant manager, allocator and finalizer on pinned, disposable PostgreSQL with both ordinary tenant roles. Use the test-only bound operation for writes. Give each test a unique marker. First show that an independent, freshly bound same-tenant observer can see a known committed positive control. Capture backend PID and full transaction ID at allocation and marker staging. All marker counts below are from independent observations after finalization.

| Case | Required observation |
| --- | --- |
| Commit or caller rollback after checked return | Marker is visible on the writing backend and invisible to the observer before finalization. Commit leaves exactly one matching marker. A caller exception after return leaves zero. In both cases the unit is closed and reuse on a later lease causes zero dispatches. |
| Caught error after an insert | Raise in the bound operation after a real marker insert, and separately fail its return check or return the wrong type after the insert. Catch each error inside the body, confirm libpq still reports `INTRANS`, then exit normally. Expect `TRANSACTION_FAILED`, zero native COMMIT calls and zero committed markers. Repeat with a real SQL error (`INERROR`). |
| Binding and single use | Exercise the selection states, absent operation, wrong tenant/nonce, foreign batch or full transaction ID, wrong action or bundle, and an already latched unit. Each gives zero dispatches. An equal attempt value on the correctly bound unit works. Duplicate or caught re-entry gives at most one dispatch and zero committed markers. A foreign thread cannot change the owner's outcome. |
| Finalization and trust surface | Retain the lost-COMMIT-response and cleanup cases. The guard never repeats dispatch. Run the production reachability, facade, constructor, slot and line-budget regressions, including a fixture import and public override that the checker must reject. |

**Handoff.** #422 owns the production-writer rollback, commit and caught-error tests. They count real claims, validation records and links, verify the returned ID, bytes and evidence, and require same-batch promotion reachability. #178 owns the protected-read wait, old admission and exact retry with zero extra dispatches. Neither is needed to verify #424's transaction markers. [Writer delivery](https://github.com/samovers/OFARM2/issues/422) · [Coordinator delivery](https://github.com/samovers/OFARM2/issues/178)

This is provisional repository development. An unbound production call fails closed. If a supported caller must transfer an open context between threads, the result check must use a second transaction, or the selector cannot furnish the required per-unit binding, stop before enabling the call. The respective owner must redesign the lease, readback or selection interface, followed by review and a new decision for any changed boundary or invariant. Production activation and deployment require their own authority.

The implementation consumes the bound operation before reading its projection. In-progress and spent operations have identical refusal behavior. The existing unit tracks closure and rollback-only. The application and worker role use the same production manager.
