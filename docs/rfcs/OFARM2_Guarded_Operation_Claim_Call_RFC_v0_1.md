# Guarded operation-claim call on the tenant transaction

Phase A for [#424](https://github.com/samovers/OFARM2/issues/424). The primary trust boundary is **tenant transaction ownership and finalization**. [#178](https://github.com/samovers/OFARM2/issues/178) is the caller and [#422](https://github.com/samovers/OFARM2/issues/422) is the writer.

## One call and one owner of commit

Add a synchronous, typed `stage_operation_claim(attempt)` operation to the live `TenantUnitOfWork`. Its successful return means that the writer staged the claim and its validation evidence on this transaction. Only the manager can make those writes durable. The primary risk is that a Python failure after a successful insert leaves PostgreSQL able to commit a partial claim. Contain it by including dispatch **and verification of the writer return** in the existing rollback-only protection, before returning anything to the caller. [Current finalization behavior](../../kernel/tenant_uow.py) · [Tenant failure handling](OFARM2_Tenant_Transaction_Failure_Handling_RFC_v0_1.md)

| Owner | Supplies and controls |
| --- | --- |
| #178 command coordinator | Repeated saved-result lookup under the uniqueness guard, new-attempt disposition, selected action and assertion-command binding, protected inputs, prior admitted result binding if one exists, and the eventual complete outcome. On an exact replay it never calls the writer. |
| Tenant transaction manager (#424) | Already bound connection, active unit, allocated batch, one invocation in that unit and exclusive finalization. It checks these against the coordinator's attempt and prevents a caught failure from becoming a commit. |
| #422 assertion-domain writer | Exact assertion bytes and their validation, transaction-local staging of the assertion and validation evidence, and the typed return. It uses the claim-specific storage operation on the same backend. |
| Kernel Commit Ingress | The promotion trace and the same-batch link to the assertion, using actual gate outcomes. #178 coordinates this owner in the complete transaction. #424 never assigns authorizations or constructs a gate verdict. |

The protected assets are the tenant's pending claim, its evidence and the surrounding transaction. Request fields, caller keys, supplied IDs, arbitrary callbacks, verdicts and references are untrusted. Trust the deployed registrar, the authenticated tenant binding, the coordinator's transaction-local admission and the selected owner outputs at their checked boundaries. Database administrators, compromised deployment code and arbitrary in-process reflection are outside this model.

## Dispatch

1. Preserve the current tenant login, binder, connection pool and transaction isolation. On the coordinator's guarded new-attempt path, select the applicable assertion-command binding **before** allocating the batch. Main's `COMMIT_OPERATION_CLAIM_DRAFT` selector refuses once a batch exists and forbids emitting assertions. Neither a matching batch operation string nor this draft selector admits the new call. [Draft command membership](OFARM_Operation_Claim_Draft_Temporal_Command_RFC_v0_1.md#durable-batch)
2. The coordinator supplies its original, transaction-local attempt to the unit. Bind the call to the live unit and the manager-captured tenant/principal, original attempt, action, selected bundle, batch ID and full transaction ID. Compare the request and proposed assertion ID to the independently authorized intent. A deserialized copy or caller-supplied equality flag is insufficient. The request may never choose the writer or pass a function. The deployed manager supplies a private, fixed operation just as it supplies its existing batch allocator.
3. Move the invocation from available to in progress before calling the writer. Use the bound physical transaction for staging. The public facade and the domain API expose neither arbitrary SQL, a pool checkout nor commit, rollback or savepoint controls. Reserve one call even when the same request re-enters during validation. Any overlapping invocation fails closed. Restrict the synchronous operation and its transaction-local handle to the owner of the open unit, so that another thread cannot race finalization.
4. Inside the guarded call, require the writer's complete return and match its result ID, schema, contract and complete result digest to the admitted attempt and staged bytes. Resolve the trace and domain payload on this transaction and apply #178's single result-binding check to their bytes, digests and subject. #422 evaluates the domain rules once. The hook checks that its return matches those staged outputs. A verified return contains the staged assertion ID, its complete digest, the selected schema and contract and the trace reference/digest. #178 owns persisting the original operation result and receipt. [Result-binding rule](https://github.com/samovers/OFARM/blob/b1abe2c93c7ca8b7a94a11bdb0fded64bb2e75e6/package_meta/history/clean_baseline_migration/phase_reports/not_required_transaction_and_consumption_protocol_rfc_candidate_v0_1.md#L396)
5. On any failure once dispatch starts, mark the unit rollback-only before returning a refusal or propagating the original exception, including a `BaseException`. This also covers a malformed return or a digest check failing after writes. Never clear that flag on a caught error or a nested call. On completion, invalidate the invocation so a second call cannot stage another assertion. On unit exit replace the live operation with a closed sentinel. A retained handle cannot access a returned or reused connection.

The manager checks the existing rollback-only latch on normal body exit. A caught post-insert failure therefore yields `TRANSACTION_FAILED`, including when libpq still reports `INTRANS`. An escaping body exception after a normal writer return rolls back as it does today. After a verified return, #178 still has to finish all required gates, link the promotion evidence and persist the complete result, consumption and receipt. Its later failures must abort the outer transaction. A failure after COMMIT has been sent retains the existing `FINALIZATION_UNKNOWN` and reconciliation behavior. The hook never retries an uncertain commit. [Successful transaction order](https://github.com/samovers/OFARM/blob/b1abe2c93c7ca8b7a94a11bdb0fded64bb2e75e6/package_meta/history/clean_baseline_migration/phase_reports/not_required_transaction_and_consumption_protocol_rfc_candidate_v0_1.md#L651)

## Implementation scope

Extend the public method, constructor and slot allowlists together with their drift tests. Main uses 579 of 600 lines in `kernel/tenant_uow.py` and 1,247 of 1,280 in the tenant transaction group. Reuse the existing failure latch, manager and cleanup rather than introducing a second transaction runner. Count any extracted transaction code in the same group. Measure the final change and justify any required budget adjustment in review. Preserve the existing allocator, selector and historical checks. [Architecture limits](../../conformance/rewrite_architecture_check.py)

This change needs no database migration, new role, public endpoint or second ledger. A fixed claim storage operation, selected admission and an owner-supplied writer are prerequisites to an enabled call. A missing component leaves the call unavailable without SQL. Changing commit ownership, admitting candidate bytes, relaxing a database constraint or implementing the assertion validator requires review in its own boundary. The design is provisional until the participating owners pin these interfaces.

## Acceptance

Use production entry points and a disposable pinned PostgreSQL server with the ordinary application and worker roles. Give each test a fresh tenant-scoped attempt, batch and assertion ID. A freshly bound observer must first see a known committed record for the tenant. Capture staging on the writing backend before testing visibility from the observer. Distinguish transaction-only controls from a run with the admitted #422 writer.

| Invariant | Focused test |
| --- | --- |
| Only an admitted new attempt reaches the writer | Try a replay, caller callback, missing or foreign batch, wrong tenant or unit, old attempt or draft-only selection. Each gives zero writer calls and zero claim writes. A valid new attempt dispatches exactly once. |
| One physical transaction and one finalizer | Compare backend PID and full transaction ID across binding, batch and staging. Check the facade and writer import/surface rules for access to raw connections and finalization. Attempt re-entry, an overlapping call and use after unit exit. No second dispatch or use on a later lease is possible. |
| Successful return is provisional | Read staged claim and evidence on the writer connection and observe zero new rows from another connection. Make the caller roll back after return. A fresh observer counts zero attempt claims, evidence records and links. |
| Normal commit exposes the exact returned write | After caller finalization, independently count exactly one pending assertion, compare its authorized, returned and stored ID, recompute its entire digest, and resolve and verify the returned trace and payload. Require same-batch promotion reachability. |
| A caught failure cannot commit | After real inserts, fail in Python before returning or while checking the return. Catch the error inside the body, leave PostgreSQL in `INTRANS`, then exit normally. Require `TRANSACTION_FAILED`, no native commit and zero claims and new evidence. Repeat with a database error, a substituted result ID and mismatched evidence. |
| The manager owns ambiguous outcomes | Keep the existing lost-commit-response and cleanup regressions. An ambiguous commit never causes the guard to invoke the writer again. |
