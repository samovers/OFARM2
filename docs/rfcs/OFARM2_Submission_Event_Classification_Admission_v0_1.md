# Admit an existing event classification for one pending submission

Phase A, decision version 2, for [Delivery #452 and draft #456](https://github.com/samovers/OFARM2/pull/456). The primary trust boundary is **runtime Event Ingress classification and evidence admission**. The proposed operation reads and checks one already-produced, independently stored proof before the domain validator uses the event. It returns a provisional binding for the original attempt. Version 1 was withdrawn after [three review findings](https://github.com/samovers/OFARM2/pull/456#pullrequestreview-5981210017).

## Which sources can pass

Only `PREEXISTING_PROOF` is eligible in this version. Require the selected proof and its authorized producer provenance to be retrievable from a governed source committed before this evaluation. Refuse `VALIDATION_PHASE_PROOF`, absent custody, or disagreement between production modes in the independent context and proof. This refusal happens before creating or storing a proof, invoking a domain verdict or staging a claim. An offline pass for a validation-phase proof cannot open this route. The separate [tenant evidence-storage delivery #457](https://github.com/samovers/OFARM2/issues/457) must establish the authorized record kind, writer and tenant-scoped retrieval for a live pre-existing proof. There is no identified production write path for validation-phase proof custody. Supporting it later requires a custody decision, lawful atomic membership and a new Event Ingress decision.

Use the exact event revision or digest associated with the authorized intent. When the intent has no associated world event, require an independently issued submission-act envelope tied to the same actor, scope, original submission and intended assertion. Its issuance and prior promotion edge belong to [#453](https://github.com/samovers/OFARM2/issues/453). [#451](https://github.com/samovers/OFARM2/issues/451) supplies the normalized request and its disposition. A missing original, mismatched tenant, actor, scope, subject, attempted operation or event must refuse. Only the domain writer decides subject, time and body compatibility. [Domain contract §7.3](https://github.com/samovers/OFARM/blob/6c5c6eb754baecfa38b7e364fc3d0318ae1ad89f/package_meta/history/clean_baseline_migration/phase_reports/assertion_record_submission_protected_effect_contract_rfc_candidate_v0_1.md#L459-L480)

Select the authorized issuer, exact event and request originals, profile, context and proof through trusted composition independently of the offered bytes. Verify the contract, profile and context raw SHA-256 pins, exact envelope and request byte hashes, and selected proof reference and whole-value JCS digest. Custody preserves the original proof octets too. Its canonical identity tolerates serialization whitespace; original envelope and request byte checks do not. Check classification under the selected profile, dominant consequence, subtype, family, scopes and commit class. Require runtime provenance **and** the checker's exact `CONDITIONAL_CONFORMANCE_PASS` for these inputs before returning. Treat the pinned checker’s limit of 2 MiB per input JSON document and nesting depth of 64 as verifier limits. [Canonical candidate and reuse rules](https://github.com/samovers/OFARM/blob/2cf45bef00bcdd5e865973535646a9db8b47267d/03_machine_contracts/drafts_non_default/event_ingress_classification_proof/PROPOSAL.md#conditional-evidence-admission)

#456 obtains retained proof inputs through one private reader fixed when the guarded claim adapter is composed. Only the isolated test harness supplies that reader in this delivery. It resolves independently seeded fictional originals for the selected tenant and submission. The production reader binding stays unset, so a live call cannot admit a proof. [#457](https://github.com/samovers/OFARM2/issues/457) owns the production farm-scoped reader, including any decision to read an existing table. #456 adds no production proof lookup against `ofarm.runtime_tenant_content_blob` or any other table, even when the caller supplies a matching digest.

## Where the operation runs

1. [#178](https://github.com/samovers/OFARM2/issues/178) admits a new attempt and supplies its original identity. After the signed tenant binding, command selection and batch allocation, the coordinator calls the existing `unit.stage_operation_claim(attempt)`. The argument contains the existing command, binding nonce, batch, full transaction ID and intent. No Event Ingress source read, argument conversion or eligibility check may happen while preparing that call. Replay goes through the coordinator’s separate recovery path.
2. On the live owning thread the existing claim guard consumes its single dispatch, checks tenant, nonce, selected command, batch, full transaction ID and writability, then calls the fixed private `stage_and_verify_operation_claim` adapter. **Inside that adapter**, before #422's dependent domain verdict or any claim write, call #452 synchronously on the same physical lease using the adapter’s captured signed binding and trusted originals. Fix the source and verifier at composition. The caller supplies no SQL handle, checker, resolver, verdict or callback. Refusal raises through the adapter and out of the guard. Returning a typed failure as a successful claim or catching the exception inside the adapter would violate the contract. [Guard](https://github.com/samovers/OFARM2/blob/8d3dbfb75694b3dc257a78c7d899b63fcbf82722/kernel/tenant_claim_write_guard.py#L69-L108) · [Tenant unit](https://github.com/samovers/OFARM2/blob/8d3dbfb75694b3dc257a78c7d899b63fcbf82722/kernel/tenant_uow.py#L345-L373)
3. On verified success, pass the private immutable binding to the validator in that same call. It identifies the classified event and family, authorized submission, original raw hashes, proof ref/digest and source revisions, bound to this tenant, nonce, batch, transaction and attempt. The claim adapter completes #422 validation/staging and #178 checks its existing typed return. #178 owns the per-attempt orchestration and supplies the checked binding to #428's fixed resolver on that lease, verifying all the same bindings again. Keep any provisional handoff private to the owning attempt, with no bearer token, process-wide cache or public change to `ClaimWriteAttempt` or `CheckedClaimResult`. For a world-event association also follow the checked domain trace's event evidence ref/digest. For a submission act use the independently established act and original admission. A domain trace with legitimately inapplicable association fields cannot stand in for it. If #178 cannot supply the same verified admission to both consumers, live composition refuses. [Approved claim adapter](https://github.com/samovers/OFARM2/blob/8d3dbfb75694b3dc257a78c7d899b63fcbf82722/docs/rfcs/OFARM2_Guarded_Operation_Claim_Call_RFC_v0_1.md#authority-and-call-order)
4. On failure, `stage_operation_claim` catches `BaseException`, latches rollback-only and re-raises before its caller can catch the refusal. Normal exit rolls back the already allocated batch, even after PostgreSQL is restored to `INTRANS`. A later failure in promotion is covered separately by [#436](https://github.com/samovers/OFARM2/pull/436). Only the tenant manager finalizes. Its factory is currently unbound. This design reuses the guard, its lifetime checks and its original result type. A standalone public admission call, a required rollback for a skipped entire staging call, or an early check outside this guard would need a separate tenant transaction-owner delivery. [Finalization](https://github.com/samovers/OFARM2/blob/8d3dbfb75694b3dc257a78c7d899b63fcbf82722/kernel/tenant_uow.py#L584-L612)

## What remains retrievable after commit

The source owner retains the earlier immutable proof, producer provenance, selectors and the original bytes or protected references to them. #452 issues no receipt or durable row. Its fresh decision for this attempt is provisional until #178 includes the applicable passing gate trace and its exact source binding in the complete success receipt. #428 stores the original normalization reference and classification proof reference in `INGRESS_NORMALIZATION.relatedArtifactRefs`, with the matching request ID, event ID and verified family. After commit a fresh observer follows the receipt's gate trace to those exact immutable sources and compares the recorded disposition, bindings and digests. That is readback of the original admission. The checker’s transient diagnostic report is not a separately promised artifact. If the original disposition and source selection cannot be resolved from the committed evidence, the coordinator must refuse success. Earlier source records survive a failed attempt. [Trace mapping](https://github.com/samovers/OFARM2/blob/96410b8e62abed00c157d7ef973c6e177e559a4d/docs/rfcs/OFARM2_Pending_Claim_Promotion_Evidence_v0_1.md#where-the-evidence-goes-in-the-trace) · [Atomic order and success membership](https://github.com/samovers/OFARM/blob/b1abe2c93c7ca8b7a94a11bdb0fded64bb2e75e6/package_meta/history/clean_baseline_migration/phase_reports/not_required_transaction_and_consumption_protocol_rfc_candidate_v0_1.md#L651-L692)

With an initial-only context, verify original admission once before the verdict. At readback, rehash and compare retained facts without running the checker again. Exact reevaluation is possible only when the original pinned context permits it and every original input and pin is unchanged. Neither readback nor reevaluation authorizes a new attempt or replay.

## Provenance is a prerequisite

Canonical [OFARM #48 / draft #49](https://github.com/samovers/OFARM/pull/49) owns acceptance of the proof contract, schemas and executable checker. The cited design commit `2cf45bef00bcdd5e865973535646a9db8b47267d` is three commits ahead of canonical main `4a3d88ea6eff4b3f8a2c521dc621595cbfd1657b`. The proof component is absent from that main tree. The draft or a GitHub test merge supplies no eligible extraction pin. No extraction or checker invocation is needed for this Phase A revision. Before implementation imports or executes the checker, verify canonical acceptance and select the actual canonical main commit containing the eligible non-default component. Preserve each original source path, accepted commit, destination and raw SHA-256 in `contracts/CONTRACTS_MANIFEST.json`, with `status: EXTRACTED_VERBATIM` and a currentness note explicitly preserving `DRAFT_NON_DEFAULT`. Retain the canonical folder status. Carry the contract, its five owned schemas and two source schemas, four pinned semantic-source originals, source pins, dependency manifest and the adjacent checker/helper code as a checked closure. Verify bytes against their individual canonical paths across the contracts, runners and fixtures lanes. Use fixed package and source roots and the qualified local dependencies, including the pinned RFC 8785 implementation, with no request-selected module, file, URL or download. A missing or drifting member, raw pin, schema or dependency refuses before admission. Canonical acceptance of non-default material grants no runtime source authority or promotion to current/default. Re-review changed adopted bytes; changed semantics or authority require a new decision. ## Verification and limits

Protect the tenant's submission identity, originals and single-use gate decision. The primary risk is admitting another submission’s plausible proof, or allowing a caught refusal to leave a committed batch. Trust the signed tenant binding, fixed adapters, independently governed source and verified canonical package. Caller-proposed source paths, status strings and hash fields confer no authority. Compromised source administrators, database owners and arbitrary execution inside trusted code are outside this design.

Run the real admission operation through the existing guard in an isolated PostgreSQL composition under **each** of `ofarm_app` and `ofarm_worker`. Seed fictional committed sources and a separate visibility control. Keep default production composition closed. Distinguish these implementation proofs from the later positive receipt and complete transaction through #178.

| Case | Required observation |
| --- | --- |
| Good pre-existing proof, both event routes | Compare exact event, original bytes, digests and family before the domain call. Independently read the committed control and source before and after outer commit. In the later integrated #178 case resolve the receipt, checked gate, originals and sole claim promotion link. On an explicit rollback the source survives and all new success members disappear. |
| Early Python refusal | Allocate a real batch and see it on the writer. Inside the guarded adapter refuse an absent proof, validation-phase timing, substituted same-family event, changed bytes, foreign source, wrong attempt or caller-selected pin. Catch the error outside `stage_operation_claim` but inside the managed body and exit normally. Require zero domain-writer and promotion calls, `TRANSACTION_FAILED`, zero native commits and no batch, claims, new gate or promotion traces, links or success receipts for that attempt. A fresh same-role observer must see its earlier source and control. |
| SQL error and savepoint | Inside the guarded call, the test reader executes `SELECT fixture.missing_proof_bytes FROM (VALUES ('fictional'::bytea)) AS fixture(proof_bytes)` on the same physical lease that allocated the batch. The inline fixture lacks that column, so PostgreSQL raises `42703` under either tenant role without reading a production table. In one case let the database error propagate directly. In a separate case roll back to the test savepoint, confirm `INTRANS` and the earlier batch on the writer, then re-raise the original error through the guard. Catch it outside the guarded call but inside the managed body, exit normally and verify the same zero-commit and observer results. |
| Duplicate, re-entry, foreign thread and expired lease | A second or nested use on the owning unit latches failure with at most one dispatch. A foreign thread or retained unit after exit, including after physical connection reuse, refuses before any source read or dispatch and cannot poison the rightful owner's healthy unit. |
| Source and readback integrity | Refuse absent custody, missing contract or changed checker/helper/schema/source pins, unsupported limits, substituted actor/intent, or proof from the dependent verdict. Initial-only readback makes zero checker calls. Explicitly allowed exact reevaluation checks the same immutable inputs. Altering the recorded disposition, proof reference or source digest must prevent a successful readback. |

Expected implementation areas are a private Kernel admission component, its focused tests and inventory, and the conditional manifest-backed extraction described above. The smallest complete change is one verifier inside an already guarded call. It grants no source write, new manager method, migration, new credentials or public route. [#457](https://github.com/samovers/OFARM2/issues/457) owns proof custody, #178 owns production composition, command identity, receipt and replay, #422 owns domain validation and #428 owns promotion evidence. A change to the boundary, effects, ownership, timing, named PR or deployment posture requires a new decision. The package and architecture checks, focused tests and scoped implementation review precede the later delivery gates.
