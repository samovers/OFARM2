# Bounded signing-authority observation — Phase A v0.1

**Recommendation:** keep one `SigningAuthorityReader` and its existing validators. Replace its blocking database retrieval with one private, synchronous poll loop over the pinned psycopg 3.3.4 `pq.PGconn` API. On expiry/cancellation, dispose of that owned connection and return the existing unavailable classification. No worker, process, event-loop conversion, cache, retry or generic cancellation framework is selected.

Primary trust boundary: **signing-authority observation integrity and availability**. Delivery [#406](https://github.com/samovers/OFARM2/issues/406), under tracking epic [#167](https://github.com/samovers/OFARM2/issues/167), owns this separate prerequisite for [#404](https://github.com/samovers/OFARM2/issues/404) / [PR405](https://github.com/samovers/OFARM2/pull/405) PS11. It also covers the same authority reader used during ordinary tenant entry, startup and minting. This named-draft candidate is design only; H1 remains unaccepted and no implementation approval or runtime acceptance is claimed. The same draft will carry the complete implementation, tests and necessary mechanical companions after approval; this RFC is not a separately mergeable process-only companion. PR405 is not changed.

## Capability, effects and support decision

A fresh authority read must either produce the same fully validated database/receipt authority as today or return control after a supported transport failure/cancellation, owning no live resource. The current reader opens a separate blocking connection during capability minting; a black-holed query or connection-context COMMIT reply can hold PR405's observer lease indefinitely under its current interface.

Permit a reader-local transport deadline, cancellation input, finite admission, fixed-query nonblocking I/O and a narrowly owned production construction path. Preserve every database function, field, authority predicate, receipt signature/canonicalization/freshness/equality check, credential, KMS call rule and failure class. Do not change principal resolution's shared connection factory, tenant/audit decisions, grants, schemas, key custody, public routes or authority clocks. No new database writes. The server's read-only observation function remains the sole authority source.

**Support choice H1 must be explicit in the S1 decision:** recommend exactly one explicit DNS-free endpoint (one numeric hostaddr with the existing host/TLS identity retained, one literal numeric host, or one admitted local Unix socket directory) and regular receipt/configuration files on healthy local storage. Multiple configured endpoints are refused, including comma-separated host/hostaddr/port lists. No DNS resolver, remote/FUSE filesystem, FIFO/device receipt, interactive authentication or external credential callback may run inside this promised bounded path. The current config parser accepts wider DSNs and arbitrary absolute receipt paths; it has not already adopted this restriction. No live deployment values were read or invented. If multi-host routing, hostname-only discovery or blocking remote receipt storage must remain supported, revise H1 and this design before coding. Do not silently resolve and cache addresses, weaken TLS, or call synchronous DNS outside the deadline and claim success. See the H1 decision section below.

This is the smallest proposed pre-deployment slice under H1. A finite local operating-system call is an assumption, not a hard real-time guarantee for a hung kernel/storage device. Such host failure is excluded; remote database reply loss is included. If evidence invalidates H1, revise the design rather than grow a hidden worker fallback.

## One retrieval and disposal path

The private interface remains `current(kid)` with optional keyword-only `cancel_event` and `deadline_monotonic` supplied only by trusted internal callers. Missing arguments still use the mandatory owner limit. `TenantCapabilityIssuer.mint` passes these through and checks cancellation/expiry before calling KMS. PR405 supplies its cancellation event through the existing minter path in its own integration. Startup uses exactly the same reader; there is no legacy unbounded path.

Set a proposed **5-second total reader limit**, reduced by an earlier caller deadline, with a **50 ms maximum socket-poll interval**. The same absolute monotonic deadline covers connect, query/result receipt, disposal checks, local receipt retrieval and validation; it never restarts per stage or per address. Monotonic time only stops work: database `observed_at_us` continues to drive all authority/receipt time decisions. Permit at most **8 reader calls in flight per reader instance**, including cleanup, with nonwaiting admission; the ninth receives `SigningAuthorityUnavailable`. This matches the current tenant pool's maximum concurrent consumers without claiming that the authority connections belong to that pool. One admitted call owns at most one PGconn, one selector, one complete result and one receipt descriptor; no background task survives it.

1. Check cancellation, deadline and admission before allocating resources. Build the reader's explicit connection parameters from the existing configured route and credentials, validate H1, and preserve TLS identity/options. Require exactly one explicit host/hostaddr route and one numeric port; for a socket route require one explicit absolute directory. A host paired with hostaddr supplies identity for that same endpoint, not a second endpoint. Refuse host/hostaddr/port lists, empty/default route entries, mismatched pairs, service/servicefile expansion and route values inherited only from PGHOST/PGHOSTADDR/PGPORT or libpq defaults. Inspect relevant PG* environment inputs without changing them; any input that could select an additional or unresolved route must be refused. Explicit admitted route parameters must override environment defaults when passed to libpq, never silently select one member of a list. No endpoint is invented or resolved/cached. Hidden DNS/credential callbacks are outside H1 and must be refused before connecting; local TLS/password files are subject to the same local-I/O assumption. Do not mutate ambient environment or the principal reader's factory.
2. Use `pq.PGconn.connect_start` and `connect_poll`. Poll the current `pgconn.socket` for the state requested by libpq, rereading it after each connect-poll because it can change. Every wait is at most `min(50 ms, remaining budget)` and checks the event before and after. `connect_timeout` does not govern this low-level poll API. No new checkout, reset, application retry or secondary route is attempted after failure. Successful connection enters nonblocking mode.
3. Send the existing column projection and `ofarm.observe_signing_authority` call through `send_query_params`, with one text parameter for kid. Use `$1` as the native protocol placeholder; keep one column inventory derived from `SigningAuthority`, not a copied list. Use `flush`, socket readiness, `consume_input`, `is_busy` and `get_result` under the same deadline. Never call synchronous `exec_`, `exec_params`, cursor execution or a cancellation handshake.
4. This is one fixed SELECT in its implicit transaction. The existing function's exact source reads/validates state and returns a row; it does not append authority acts. No explicit BEGIN/COMMIT exchange is needed. Require one completed TUPLES_OK result, exactly one row, the exact column shape, complete result-stream drain and transaction status IDLE before it is eligible. A lost ReadyForQuery or extra result refuses; merely receiving a row is insufficient. This replaces the old connection-context COMMIT with complete single-statement completion, not with assumed success. No writable callback or arbitrary SQL parameter is exposed.
5. Convert fields using psycopg's registered text loaders and the connection's actual encoding/adaptation context, then invoke the unchanged `SigningAuthority.from_database_row(row, kid)`. There is no new UUID/integer/bytea parser or authority validation path. Missing loader, wrong shape, NULL or malformed type refuses. Use a `Connection(pgconn)` wrapper only as driver adaptation context if needed; do not execute through it or enter its transaction context. Ownership of the underlying PGconn must remain single and explicit.
6. Close the selector, clear result storage after extracting the owned values, and call `PGconn.finish()` exactly once in the owning thread on every exit, including partial/failed connect. Keep nonblocking mode while finishing an established session. No remote rollback/cancel acknowledgement is required for this disposable read connection; never return it to a pool. Full result completion is required for success; cancellation before completion discards all provisional data. Closing the local client does not assert immediate termination of the remote backend. Existing server statement/role limits still apply, and no remote query is retried.
7. Read the configured receipt afresh for this call after database disposal. Open with nonblocking/close-on-exec flags, require a regular file by `fstat`, read at most `SIGNING_EVIDENCE_MAX_BYTES + 1`, close in `finally`, and preserve the existing size bounds. Healthy local regular-file open/read/close are admitted finite operations; the event/deadline is checked before and after them. File type checking alone does not prove a mount local, so H1 also binds the deployment choice. Symlinks are not authority: their resolved target must meet H1. No receipt cache, startup-only receipt, relaxed match or remote retrieval fallback is introduced.
8. Run the unchanged `SigningEvidenceVerifier.verify(receipt_bytes, now_us=authority.observed_at_us)` and `authority.require_receipt(receipt)`. Final publication checks cancellation and deadline once more. Only then return the immutable authority. Cancellation/timeout, admission failure or transport errors map to `SigningAuthorityUnavailable`; minting keeps its current `CapabilityMintError` translation. Existing receipt/authority mismatch refusals remain exact. Never log DSNs, credentials, raw evidence or SQL errors.

A success is decided at the final cancellation/deadline check after validation and cleanup. Cancellation observed before that point suppresses the result and KMS dispatch. It cannot retroactively revoke an already returned authority or undo a dispatched KMS request. The issuer checks again immediately before KMS; an already-started KMS RPC retains its existing timeout and custody rules. S1 is the reader dependency, not a new instantaneous KMS-cancellation guarantee. Process-control exceptions such as KeyboardInterrupt/SystemExit still clean up in `finally` and propagate; they are not swallowed as an ordinary refusal.

## Threats, invariants and ownership

Trusted: admitted deployment route/local storage, PostgreSQL function/projections, driver, host scheduling and the existing receipt verification key. Untrusted: partial responses, malformed/duplicate rows, stale/conflicting receipts, supplied kid, deadline/cancellation races and remote transport availability. Caller-provided timing can only shorten work, never authorize signing. Database-owner or in-process compromise and a hung local kernel are excluded; a black-holed network is not.

One reader and one validation path own the returned fact. A cancelled/expired call cannot publish later, hold a cleanup slot forever on remote I/O, or leave a worker behind. No timer thread calls `finish` concurrently with libpq. No delayed/cached authority bypasses the database observation. Principal, binder, signer and receipt authorities do not move. The acceptance-control table below supplies a reachable negative case for each invariant and the required positive case.

Expected implementation areas: `kernel/signing_authority.py`; one private `kernel/signing_authority_io.py` for this fixed transport/file operation; narrow reader construction in `kernel/application_runtime.py`; keyword propagation/pre-sign refusal in `kernel/tenant_capability_issuer.py`; owned tests and architecture accounting. Preserve `signing_receipt.py` validation, `google_kms_signer.py`, `principal_resolver.py`, shared `_connection_factory`, runtime configuration semantics outside H1's reader admission, migrations and PR405. Delete the superseded production `ConnectionFactory`/receipt-I/O path for this reader; keep no alternate production bypass.

Current source has 212/250 lines in signing_authority, 161/180 in issuer and 221/230 in application_runtime. Propose a 260-line ceiling for the one new private module and include it in the capability-signing group, increasing that group's 1,000 ceiling to **1,260**. Keep existing module/function/import/authority guards. These are prospective budgets, not measured implementation; return a concrete offset or revised budget if complete clear code does not fit. Mechanical RuntimeBundle coverage, if required by the existing manifest owner, records only the same owned code; it grants no startup/readiness authority.

## H1 — support profile requiring an explicit owner decision

**Recommended choice:** S1 supports exactly one explicitly configured endpoint whose libpq connection setup performs no DNS or external credential-service work, and receipt/configuration files on healthy local storage. One numeric hostaddr may accompany the unchanged hostname so TLS verification still uses the intended server identity; one literal numeric host or explicitly admitted local Unix socket directory is also suitable. Refuse multi-host/hostaddr/port lists, empty/default route entries, service expansion and environment-only or unresolved route selection. Read relevant PG* inputs without mutating them and pass explicit admitted route parameters so libpq cannot select an additional endpoint. No address is invented and no credentials/TLS checks are weakened.

This is an actual compatibility choice: today RuntimeConfig checks DSN syntax and an absolute receipt path, so it does not establish these conditions. The design cannot silently call an arbitrary synchronous resolver or filesystem operation while promising that a socket poll deadline can interrupt it. The selected poll mechanism is proposed for the recommended profile; its implementation and failure controls remain unproved. It cannot claim to support every syntactically accepted DSN/path.

The exact question for the S1 decision is: **May this signing-authority reader require one explicit DNS-free endpoint, refuse multi-host/service/environment-only routing and external authentication callbacks, and refuse receipt storage outside the admitted local-file profile?**

- **Accept the narrow profile (recommended):** use the concrete Phase A, retain the existing host/TLS identity and authority/receipt checks, and prove admission plus transport/cancellation controls. No broad resolver, cache, helper process or principal-reader change is needed.
- **Require wider support:** do not implement this Phase A as if it covered that profile. Multi-endpoint routing needs its own explicit admission/attempt contract. Blocking I/O needs a separately reviewable isolation mechanism that owns and terminates the operation, without abandoned work or late authority publication. Neither alternative is selected or claimed designed here.

A concrete numeric endpoint and local path are deployment inputs, not values an agent should infer or expose in this packet. Existing OFARM authority, receipt authenticity/freshness, signer custody and principal resolution are not up for selection. This choice is not permission to alter PR405 or implement S1.

## Primary source support

PostgreSQL documents nonblocking connect only under stated restrictions: avoid DNS, use the correct socket readiness and account for a socket changing between polls. `connect_timeout` does not govern this poll API; the caller supplies the deadline. Failed/abandoned connections still require disposal. These restrictions are why H1 is a real configuration/support decision. [PostgreSQL 17 connection-control documentation](https://www.postgresql.org/docs/17/libpq-connect.html#LIBPQ-PQCONNECTSTARTPARAMS)

The asynchronous command API permits send/flush/consume/busy/result handling. A caller must drain the whole result sequence; successful row receipt alone is not completion. This design additionally requires transaction status IDLE before accepting the observation. [PostgreSQL 17 asynchronous-command documentation](https://www.postgresql.org/docs/17/libpq-async.html)

For the locally loaded libpq 18.0, `PQfinish` calls connection close and memory disposal. The close path makes a best-effort Terminate send before dropping the connection; it does not establish a remote cancellation acknowledgement or immediate backend termination. Keep an established connection nonblocking through disposal. The future target-platform control must verify this behavior with its actual loaded library under remote response loss. [PostgreSQL REL_18_0 connection source](https://raw.githubusercontent.com/postgres/postgres/REL_18_0/src/interfaces/libpq/fe-connect.c)

## Simpler alternatives considered

| Alternative | Concrete reason it does not deliver the selected invariant |
| --- | --- |
| Add connect/statement timeouts to the existing factory | A server timeout cannot force delivery of its reply; connection-context cleanup can also await a lost reply. Changing the shared factory expands into principal resolution |
| Use stock cancellation or wrap the existing async reader | Pinned source attempts cancellation and then waits again. It is not evidence of finite disposal when the original response remains unavailable |
| Run the blocking reader in a thread and stop waiting | The connection/file operation and worker can remain alive; cancellation does not own and end the work or prevent accumulation |
| Add a per-call process | Process termination could isolate broader blocking operations but adds another lifecycle and result-transfer path. It is not necessary for the proposed H1 profile and is not designed here. If H1 is rejected, the present design must be reconsidered explicitly |
